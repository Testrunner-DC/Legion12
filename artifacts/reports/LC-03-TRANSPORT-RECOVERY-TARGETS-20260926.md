## 2. 分目标

### G1｜连接代际与恢复收敛

在同一权威对局中建立旧连接、替代连接和普通观战连接。于对局状态变化后执行真实断线/重连，证明：

- 新连接代际严格递增并继承同一房间、对局和权威 Revision；
- 旧连接收到 superseded 或在传输层关闭，不能再覆盖新连接；
- 新连接恢复必须先得到完整权威状态，不能把旧连接的增量基线带入新连接；
- 再次 `syncState` 与恢复后的完整状态收敛。

### G2｜重复、延迟、乱序和过期请求

以真实 WebSocket 发送带稳定 `requestId` 的操作，覆盖：

- 同一请求重复提交只产生一次权威效果；
- 同一请求 ID 携带延迟到达或不同负载时，不得再次执行；
- 已被替代的旧连接提交必须被安全拒绝或在传输层失败；
- 拒绝路径不增加 Revision、事件、Prompt、录像命令或动画触发次数。

### G3｜快照/增量仲裁

客户端声明 `deltaGameState` 能力并维护本地投影：

- 增量只能应用于匹配的 `matchId`、`baseRevision`；
- 断线前收到的旧增量不能应用到重连后的新完整基线；
- 完整快照与按序增量重建的接收者状态逐字段一致；
- 强制恢复、Prompt/行动权等关键状态不得被可替换增量吞并或重复结算。

### G4｜三类真实接收者隐私

对玩家 0、玩家 1、普通观战者分别捕获真实网络消息，并以结构化字段断言：

- 玩家只能看到自己的私有手牌实例，不能看到对手私有手牌实例；
- 普通观战者不能获得任一玩家私有手牌、私有 Prompt 或 GM/裁判增强字段；
- 重连完整快照、后续增量和 `syncState` 均保持相同权限边界；
- 普通观战者永不被升级为 `ForReferee` 或 GM 视角。

## 3. 对抗模型

1. 三个独立账号经真实 WebSocket 完成认证；两名玩家创建/加入房间并开局，第三人普通观战。
2. 客户端维护“最近完整快照 + 合法增量”状态，并记录 match、Revision、Prompt、事件与私有哨兵。
3. 玩家在关键节点提交操作；插入重复 ID、同 ID 不同负载、替代连接和旧连接延迟提交。
4. 玩家连接被同账号新连接接管；新连接使用全新 codec 基线恢复，随后继续提交和同步。
5. 三类接收者最终投影与服务器恢复消息按角色分别比较；角色之间不要求内容相同，只要求各自授权域稳定。
