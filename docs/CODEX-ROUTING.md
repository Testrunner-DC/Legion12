# 十二军团任务复杂度自动路由

## 最近工作负载结论

基于最近约两周的 Git 提交、修复台账、项目状态、测试与高频修改文件进行只读统计：

- 约 128 次提交中约 49% 明确属于 Bug 修复，规则与卡效任务是主要工作量。
- 高频模块依次集中在卡效状态机、Prompt/响应堆叠、兵力与进攻、区域移动、隐藏信息、沙盒代操作、WebSocket 状态恢复与部署。
- 最容易出错的是服务端卡效状态机；其次是对战 UI、派生兵力/职介、网络一致性、部署回滚和账号权限。
- 复杂度分布估计：快速档 10%～15%，标准档 30%～35%，深度档 40%～45%，关键档 10%～15%。
- 本项目不以快速档为默认档。涉及规则语义的任务至少进入标准档；未知根因、同类卡池迁移或跨模块卡效进入深度档；生产、网络一致性与安全进入关键档。

## 配置与验证

- 项目入口：`.codex/config.toml`
- 独立代理：`.codex/agents/l12-fast.toml`、`l12-standard.toml`、`l12-deep.toml`、`l12-critical.toml`
- 自动检查：`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-l12-codex-routing.ps1`
- 批次检查：`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-l12-change.ps1 -Level Focused|Batch|Release`

当前 Codex CLI 已验证：全部 TOML 可解析，`--strict-config` 可启动，`max` 推理强度可被解析，项目配置层能够列出四个代理及其模型配置，根 `AGENTS.md` 路由规则能够进入模型可见上下文。

## 使用限制与重新加载

Codex 只会在受信任项目中启用仓库级 `.codex/config.toml`。本仓库的规范路径位于 D 盘；若当前 Codex 会话尚未信任该规范路径，运行时会读到配置层但标记为禁用。为遵守“不擅自修改全局权限、认证或外部服务配置”，本批不会改写用户级 Codex 配置。

启用步骤：在 Codex 中信任该 D 盘仓库后重新打开项目或重启当前任务。重新加载后运行上述路由验证脚本；若当前工具不能按自定义代理名称派发，则按照独立 TOML 中声明的 `model` 与 `model_reasoning_effort` 显式创建同档执行代理，不得静默降档。

第二模型只承担只读独立审计：检查规则映射、同类卡池遗漏、隐藏信息、取消/无效/来源离场边界与测试覆盖。最终裁定顺序始终为规则书、FAQ、设计者裁定和自动测试，第二模型不得直接覆盖实战实现。
