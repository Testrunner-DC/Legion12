# 十二军团变更批次与快速验证

## 目标

减少三类时间浪费：插入任务覆盖原任务、局部修改反复运行完整发布构建、同类卡牌重复修复。批次以一个公共根因为边界，不以单张卡或单个聊天消息为边界。

## 标准流程

1. 最小只读分类：读取规则、工作区状态、相关修复记录和直接相关代码。
2. 在 `TASK-LEDGER.md` 登记任务、模型档位与批准状态。
3. 保存基线：`git status --short`、相关测试结果以及变更前关键行为。
4. 为 Bug 编码失败回归或确定性场景；卡牌问题扫描全部 S01/S02 同类能力。
5. 修改公共框架并迁移同类入口；禁止恢复历史卡号 `case`。
6. 实现过程中运行 `Focused`；批次完成运行 `Batch`。
7. 复查 `git diff --check`、`git diff --stat` 和关键契约，更新修复台账及项目状态。
8. 依据既有长期授权，验证完成且远端无冲突的批次可提交、推送；部署仍需本批明确授权。先提交，再对干净提交运行一次 `Release`，检查通过才推送。部署复用该提交绑定的发布包；脏树不生成或复用旧HEAD发布包。

## 独立模型审计

- 第二模型只作为只读审计者，不直接修改实战代码或替代主代理结论。
- 审计范围优先覆盖规则映射、同类卡池遗漏、隐藏信息、取消/无效、来源离场、中断恢复和自动测试缺口。
- 审计意见必须回到规则书、FAQ、设计者裁定与可复现测试核验；四者优先于模型判断。
- 主代理负责决定是否采纳、补回归、复核 diff 并报告未解决疑问。

## 验证层级

| 层级 | 使用时机 | 行为 |
| --- | --- | --- |
| Focused | 修改循环 | 根据变更路径只运行 TOML/路由、后端规则、平台持久化或前端契约中的相关项 |
| Batch | 一个独立功能/Bug 完成 | 受影响模块完整测试；卡效变更额外运行原子审计；前端变更运行 UI 契约和生产构建 |
| Release | 已授权同步或部署前 | 调用既有完整发布验证，生成可复用的提交级产物；不得代替用户的部署授权 |

缓存由 `Initialize-L12BuildEnvironment.ps1` 统一放到 D 盘可用空间，避免重复占用系统盘。发布构建继续复用按提交哈希缓存的产物。

## 会话交接与验证去重

- 新的独立功能可另开短任务；初始只读 `AGENTS.md`、`docs/HANDOFF.md` 和相关台账条目，按需读取历史，不复制全量对话。
- 交接须包括日期、物理工作区、开发/远端/线上三个版本、已完成事项、当前待办、约束、验证和恢复证据。所有版本在下一任务开始时重新核实。
- 插入需求登记到当前批次队列，不因新消息丢弃已接受的要求；收尾逐项核对，校准台账状态。
- `Release` 的外层只负责相关审计，内部提交级验证负责一次规则/平台测试、隔离前端构建与包生成；不再两层重复完整测试。缓存只有满足当前提交、清洁工作树、资源版本及产物哈希条件才可复用。
- 提交或部署仅改变文档/工具时不自动重启业务服务。部署后的健康检查与开发期测试分开记录。
- 发布后清理是有人审阅的独立维护步骤，不在服务重启流程里盲目递归删除目录。

## 防回滚检查

- 修改前后分别记录工作区状态，禁止 reset、checkout 或覆盖本地真值。
- 每个历史修复必须有测试、UI 契约、目录不变量或审计棘轮中的至少一个守卫。
- 对天灾详情、圆形卡图、资源点击支付、遮罩层、隐藏信息、Prompt 取消等高频回滚点，优先增加行为契约，不依赖人工记忆。
- 发现与活跃批次无关的已有修改时立即绕开；无法安全绕开则停止并报告。
