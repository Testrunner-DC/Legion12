# 十二军团架构锁

状态：P0—P4完成后的长期工程约束。它锁定已经验证的职责边界，不冻结产品需求，也不禁止在边界内继续增加卡牌、页面、后台能力或运营功能。

## 一、锁定的不变量

1. **P0 卡效出口**：卡效继续通过稳定能力身份、原子目录或已验证组合流程进入唯一权威结算；不得新增卡号旁路、文案推断或前端结算副本。
2. **P1 内核边界**：单局写入权仍归`L12GameEngine`；命令、接收者投影和检查点通过既有端口表达。读取入口不得偷偷推进未声明的结算语义。
3. **P2 外围方向**：接入层和房间层只组织连接、权限与生命周期；玩家、观战者和裁判状态继续由同一投影适配器生成，不在HTTP/WebSocket层重写隐私规则。
4. **P3 持久化**：Journal V2、检查点、请求去重、哈希、结算outbox和查询投影保持唯一体系；格式版本与最低恢复版本集中管理。旧版本无法安全回放时失败关闭，不用新规则反算历史结果。
5. **P4 产品结构**：规则中心继续使用同页七子页和已发布投影；逻辑横向画布只允许显式路由加入，按实际可视区与玩家设置判定，不依赖设备身份或物理方向，不侵入桌面宽屏与普通页面。
6. **发布边界**：架构完成不等于自动部署。任何正式部署仍需要当批明确授权、完整Release、玩家更新日志和线上核验。

## 二、扩展而不绕过

- 新卡与新卡效：扩展既有能力结构、原子或经审定的组合流程，并补齐正常、取消、无效、对象失效、重复提交、恢复、隐藏信息和展示消费者证据。
- 新平台功能：从外围调用内核端口或消费已确认事实；不得参与实时卡效结算，也不得修改历史结果。
- 新分析：由已完成的权威事实生成可重建投影；玩家录像的留存策略不得影响统计事实。
- 新页面与移动布局：普通页面保持自然响应；只有确需逻辑横向画布的路由才显式加入。移动样式与桌面样式继续物理隔离并通过连续尺寸、安全区和弹框验收。
- 新规则内容：先进入后台草稿和逐项审核，发布后才进入玩家投影；保留来源与版本状态，资料未提供日期时如实标记，不伪造元数据。

## 三、变更协议

1. 每批先判断触及哪项不变量，并在任务台账记录扩展点、回滚面和所需门禁。
2. 优先扩展现有端口、结构、投影和组件；只有现有边界确实不能表达需求时，才提出架构变更。
3. 改动本文件或`ARCHITECTURE-TARGET.md`的锁定边界，必须有明确的新目标、迁移/兼容策略、失败模式、退出门槛与用户确认；不得以局部功能需求暗改架构。
4. `scripts/check-l12-architecture-lock.mjs`在本地分级验证与GitHub主线验证中强制执行；现有规则、平台、恢复、隐藏信息、移动/桌面隔离和发布门禁继续共同生效。
5. 门禁失败时修正实现或正式调整架构决策，不允许删除断言、增加宽泛豁免或复制第二套路径来“通过测试”。

## 四、允许的维护

命名整理、性能优化、UI细化、内容补充、存储压缩和内部模块拆分均可继续，只要行为仍由同一权威事实驱动、兼容策略明确、既有门禁通过。架构锁不是永久保留旧代码的理由；确认无调用、无独有数据且有回归保护的遗留实现可以删除。
