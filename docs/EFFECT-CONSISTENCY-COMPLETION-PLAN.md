# 效果一致性实施计划与完成定义

## 最终目标

任何卡效不因卡牌编号而拥有另一套资格、选择、支付、响应、结算、状态更新、公开事件或恢复规则。卡牌只提供结构化规则参数；同一类型效果由同一生命周期协议执行。

“完成效果一致性”不等于已修完当前报告的卡牌。只有下列七个阶段全部验收，且全卡盘点不存在未归类入口，才可标记完成。

## 统一生命周期

每个效果段必须按同一顺序具有可审计状态：

`资格判断 → 候选生成 → 玩家选择 → 支付费用 → 响应窗口 → 结算时复验 → 状态更新 → 事件/动效/日志 → 重连恢复`

其中“冒号前”为费用或发动条件，“冒号后”为效果。费用在入栈前支付且不会因后续无效或目标失效退款；没有合法对象的必发效果按规则跳过，已经声明的对象在逆结算后失效则明确记为失败。对象选择（手牌、场上、墓地、牌库）即使唯一也必须由玩家点击；纯资源费用可例外。

## 分阶段交付与退出条件

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| P0：卡池台账 | 324张卡、每个效果段、触发时点、区域、费用、目标、分支、响应范围 | 每个效果段都映射到一个生命周期档案；无“只靠卡号分支而未列入台账”的运行入口。 |
| P1：生命周期内核 | 资格、候选、选择、费用、响应、无效、跳过、失败、重复提交与恢复的共用工具 | 每一种结果有唯一事件状态和拒绝原因；旧的静默结束、把失败写成取消、把取消写成无效均为0。 |
| P2：对象与目标复验 | 场上/手牌/墓地/牌库/士气/符文对象，单目标、独立多目标、目标替换、临时成为军团 | 无目标跳过、全失效失败、部分失效继续；唯一对象仍需点击；当前区域与当前类型均在结算时复验。 |
| P3：费用与条件 | 士气、临时士气、符文、弃置、自伤、返还、墓地代表值与复合费用 | 冒号边界统一；不能支付不发动；支付Prompt可取消且不死锁；费用支付、无效、后段失败的关系有回归。 |
| P4：触发与分支 | 登场、阵亡/离场、进攻/击杀、主动、反击、试炼、符文、天灾、多段分支 | 每个触发族只保留一套候选、支付、响应和结算协议；卡池台账逐项有运行入口与具名测试证据。 |
| P5：呈现同源 | 图鉴卡文、按钮资格、选择弹框、响应弹框、动效、日志、回放 | 全部读取同一效果段定义及实际分支结果；文本、费用、目标、公开等级和结果状态相互一致；UI契约固定既有布局。 |
| P6：恢复与发布门禁 | 重复提交、刷新、断线、重连、堆叠恢复、回放 | 每个生命周期档案至少有正例、无目标、被无效、重复提交、重连五类覆盖；发布级全卡审计、后端、前端与回放门禁通过。 |

## 每个效果类型的最低测试矩阵

同一生命周期档案至少覆盖：

1. 正常发动与结算；
2. 无合法对象时的正确跳过或不可发动；
3. 已支付费用后被无效；
4. 已声明对象在逆结算后失效；
5. 重复/过期提交不改变状态；
6. Prompt、堆叠或选择阶段刷新/重连后可继续或可取消。

独立多目标额外覆盖“部分对象失效后其余目标继续”；所有对象选择额外覆盖“唯一候选仍出现选择步骤”。费用路径额外覆盖“误选后取消且不死锁”。

- 当前处于 **P2：对象与目标复验**。通用敌方目标结算协议以及启动卡组定向入口（莫德雷德、胡夫、乔泽、弗蕾迪斯、伊丽莎白一世、布狄卡）已完成子批验收；P2其余卡池、区域对象与类型替换路径仍按台账逐族收口。下一小批须先确定一个生命周期档案和完整扫描范围，不混入无关卡牌。
- 每一小批固定执行：先列出扫描查询和受影响卡牌 → 写失败回归 → 修改共享协议并迁移全量同类入口 → Focused/Batch → 更新台账、Bug登记与交接 → Release后同步。没有通过上述退出条件，不把该小批描述为完成。
- P5之后才进入用户已批准的后台结构化编写能力：效果撰写、勘误、收录产品、弹框/日志文本和呈现样式选项从同一后台定义维护；这不是替代P0-P6的捷径。

## 最终验收清单

只有同时满足以下条件才标记“效果一致性完成”：

- 卡池每个效果段均有生命周期档案、运行入口和测试证据；
- 七个阶段全部通过，遗留清单为零或每项有明确的产品裁定、负责人和截止版本；
- `effect-declined`、`effect-noop`、`effect-failed`、`effect-negated`及“不能发动”的服务端拒绝可互相区分，且前端、日志和回放同源显示；
- 全类异常矩阵和全卡原子审计为零缺口；
- 发布级规则、平台、UI、卡图、重连与回放门禁通过；
- 使用一组已保存的回放/状态夹具做最终回归，不依赖人工逐张临场发现问题。

在此之前，只能说“某个阶段已完成”，不能笼统宣称效果一致性已经完成。
