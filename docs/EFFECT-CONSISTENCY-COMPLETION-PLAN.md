# 效果一致性实施计划与完成定义

执行进度的唯一入口为 [EFFECT-LIFECYCLE-ROADMAP.md](EFFECT-LIFECYCLE-ROADMAP.md)。本文只维护完成定义和验收条件，避免另建一套进度。

## 最终目标

任何卡效不因卡牌编号而拥有另一套资格、选择、支付、响应、结算、状态更新、公开事件或恢复规则。卡牌只提供结构化规则参数；同一类型效果由同一生命周期协议执行。

“完成效果一致性”不等于已修完当前报告的卡牌。只有下列七个阶段全部验收，且全卡盘点不存在未归类入口，才可标记完成。

## 统一生命周期

每个效果段必须按同一顺序具有可审计状态：

`资格判断 → 候选生成 → 玩家选择 → 支付费用 → 响应窗口 → 结算时复验 → 状态更新 → 事件/动效/日志 → 重连恢复`

其中“冒号前”为费用或发动条件，“冒号后”为效果。费用在入栈前支付且不会因后续无效或目标失效退款；没有合法对象的必发效果按规则跳过，已经声明的对象在逆结算后失效则明确记为失败。对象选择（手牌、场上、墓地、牌库）即使唯一也必须由玩家点击；纯资源费用可例外。

### 次数身份与提交

2026-09-17裁定：卡文未明示不得增加次数限制；效果中点名卡名的次数限制是同名共享特例，由同一玩家的所有同名副本共用，不能按物理实例分别扣次。可选发动在拒绝时不扣次，在完整声明提交时扣次；候选/待选择与已发动必须分离。之后被无效不恢复次数；由效果生成的免费发动是否计入正常次数仍以其明示规则为准。

### 原子与效果段的边界

2026-09-17固定数量回库裁定：没有“至多／最多”时，必须满足所写数量才回牌；不足则整次不回，不等同于独立多目标各自部分执行。冒号前回库仍是必须支付的Cost，冒号后回库是可被无效的效果。洛基的回血与回库不是“随后”依赖，不足数量仍能发动并回血；免费发动不跳过冒号后可执行的回库。固定组的声明与结算均复验完整性，新增或替代对象不得填补已经失效的声明。

原子只表示可复用的基础操作，例如抽牌、弃牌、移动区域、支付士气、选择对象、兵力变化和洗切。不得为了某张卡或某段文案另造“抽牌后强制弃牌”这类专用原子。

代码中现有的`L12AtomicAbility`名称指的是**效果段容器**，不是新的专用操作原子。它把同一段卡效的来源、时点、冒号前费用、原子顺序、响应、结果和呈现绑定在一起。例如“抽牌后强制弃牌”应在一个效果段内顺序组合`抽牌 → 选择（如规则需要）→ 弃牌`；只有卡面本来就是不同的时点或可独立响应的效果时，才拆成两个效果段。

## 每个效果类型的最低测试矩阵

同一生命周期档案至少覆盖：

1. 正常发动与结算；
2. 无合法对象时的正确跳过或不可发动；
3. 已支付费用后被无效；
4. 已声明对象在逆结算后失效；
5. 重复/过期提交不改变状态；
6. Prompt、堆叠或选择阶段刷新/重连后可继续或可取消。

独立多目标额外覆盖“部分对象失效后其余目标继续”；所有对象选择额外覆盖“唯一候选仍出现选择步骤”。费用路径额外覆盖“误选后取消且不死锁”。

## 最终验收清单

只有同时满足以下条件才标记“效果一致性完成”：

- 卡池每个效果段均有生命周期档案、运行入口和测试证据；
- 七个阶段全部通过，遗留清单为零或每项有明确的产品裁定、负责人和截止版本；
- `effect-declined`、`effect-noop`、`effect-failed`、`effect-negated`及“不能发动”的服务端拒绝可互相区分，且前端、日志和回放同源显示；
- 全类异常矩阵和全卡原子审计为零缺口；
- 发布级规则、平台、UI、卡图、重连与回放门禁通过；
- 使用一组已保存的回放/状态夹具做最终回归，不依赖人工逐张临场发现问题。

在此之前，只能说“某个阶段已完成”，不能笼统宣称效果一致性已经完成。
