# 卡效独立模型验收协议

更新日期：2026-08-31

## 目的

由未参与实现的新模型独立核对卡效，降低实现者延续自身假设、只验证正常路径或用现有代码反向解释规则的风险。新模型不能把源码中的行为当作规则依据。

## 提供给验收模型的材料

1. 最新规则书原文、FAQ 与 Q&A 工作簿。
2. S1/S2 卡牌原文数据和卡号清单。
3. 可运行的服务端、前端与自动测试，但不提供“当前实现应该正确”的结论。
4. `CARD-EFFECT-STATUS.md` 仅作为覆盖索引，不作为裁定依据。
5. `OPEN-QUESTIONS.md` 中的问题必须保持未裁定，验收模型不得猜测补齐。

## 每张卡的验收维度

- 时点：登场时、进攻时、进攻后、阵亡时、主要阶段、持续效果与同一时点批次是否正确。
- 入栈：目标、模式和位置是否在入栈前声明；费用是否先支付；无效后费用是否返还。
- 区域：手牌、牌库顶/底、墓地、战场、圣物区、士气区、天灾牌库与移出游戏的移动及替代效果。
- 数值：基础兵力、当回合修正、持续修正、设定值、免死与重新计算顺序。
- 信息：公开/私有信息、双方分别确认、同时选择、对手等待提示是否符合原文。
- 交互：候选对象是否只高亮合法目标，排序/多选/位置选择是否复用统一 Prompt。
- 边界：空牌库、空手牌、场地已满、来源离场、多张同名卡、多个同时触发、效果在结算中产生新触发。

## 输出格式

完整 248 张卡的当前运行时层级与待审状态记录在 [CARD-EFFECT-REVIEW-MATRIX.md](CARD-EFFECT-REVIEW-MATRIX.md)。先从矩阵中区分“细原子已验证”“复合过渡”和“仅入清单/待迁移”，再按下列验收状态逐能力补证；运行时迁移层级不能代替独立验收结论。

每张卡只能归入以下一种状态：

- `通过`：规则路径与边界测试均有证据。
- `缺少测试`：实现看似符合，但自动测试不足以证明。
- `明确错误`：能够给出原文冲突、最短复现步骤和预期结果。
- `有疑点`：原文无法唯一裁定，必须进入 `OPEN-QUESTIONS.md`，不得由模型自行决定。
- `未实现`：卡号没有进入权威服务端流程，或只存在文字/类别识别。

每个非“通过”项必须包含卡号、原文依据、当前行为、预期行为、复现步骤、建议测试名称；涉及堆叠时需要列出优先权与结算顺序。

## 验收门槛

- 不能以“源码检出卡号”代替完整实现。
- 不能只做静态代码审查；必须运行测试，并至少补充一次规则范例式的多层堆叠测试。
- 所有明确错误修复后由同一验收模型回归，再由另一个全新上下文做抽样复核。
- 用户对规则原文的裁定优先级最高；模型只负责发现冲突和提供证据。
