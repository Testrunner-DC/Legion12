# 登记条目前向 schema（D5，自 2026-11-23 起生效）

## 为什么只对新增条目生效

`scripts/audit-l12-registry-structure.ps1` 对现有 693 条登记条目做过实测：词表归一后字段覆盖率只有 6%–17%，
未识别标签 981 种，无法归类的正文 2,742 行。把历史条目改写或 JSONL 源化都不可行，已否决。
因此这里只约束**未来**：历史条目原样保留，其正文整体就是 `bodyExtra`；不解析、不改写、不迁移。

## 生效规则

1. 条目 id 内日期 **≥ 2026-11-23** 的条目必须按下节格式书写；缺任一必填字段 →
   `scripts/verify-l12-doc-ledger.ps1` 失败并打印缺字段的条目 id（门禁红，不设棘轮）。
2. id 日期早于该日的条目**一律豁免**：结构与措辞都不检查，`git diff` 里不得出现任何历史条目的改动。
   登记表按日期**倒序**排（新条目插在 `# Legion12 Bug 修复记录` 标题之后），日期顺序规则照旧由门禁检查。
3. 只做可机检的结构检查：标签行存在即可，不解析内容语义、不引 JSONL、不写条目解析器。
4. `docs/TASK-LEDGER.md` 的日期标题沿用原有「日期不得倒序」规则，不套本节字段。

## 字段

| 字段 | 标签（行首 `- 标签：`） | 必填 | 说明 |
|---|---|---|---|
| `id` | 标题 `## TYPE-YYYYMMDD-SLUG｜标题` | 是 | 类型、日期、短标识；日期必须与生效规则可比 |
| `type` | 同上 id 前缀 | 是 | 例如 `PLATFORM` / `CLIENT` / `SNAPSHOT-WIRE` |
| `date` | 同上 id 中八位日期 | 是 | `YYYYMMDD` |
| `title` | 标题 `｜` 之后 | 是 | 一句话说清现象，状态写在括号里 |
| `status` | `状态：` | 是 | 例如 `local_verified_not_deployed` / `已修复，待部署` |
| `symptom` | `现象：`（也接受 `症状：`/`核对问题：`/`背景：`） | 是 | 可观察到的事实与证据 |
| `rootCause` | `根因：` | 是 | 机制层面的原因，不是复述现象 |
| `sameTypeScan` | `同型扫描：`（也接受 `同类扫描：`） | 是 | 全池同型检索的查询与受影响面 |
| `change` | `改动：`（也接受 `修复：`/`已实现：`） | 是 | 改了哪个文件/契约，为什么这样改 |
| `regression` | `回归：` | 是 | 新增或更新的守卫用例名 |
| `verification` | `验证：` | 是 | 门禁级别与具体数字/回执路径 |
| `rollbackGuard` | `回滚：` | 是 | 回滚动作与不得回退的守卫 |
| `bodyExtra` | 其余任意小节 | 否 | 来源、已知代价、未做事项等自由正文 |

## 示例

````markdown
## PLATFORM-20261123-EXAMPLE｜示例条目（本地已验，未部署）

- 状态：local_verified_not_deployed
- 现象：可复现的玩家可见事实，附版本与证据。
- 根因：机制原因（文件:行 + 为什么会这样）。
- 同型扫描：检索命令与全池受影响数量。
- 改动：改了哪些文件与契约，为什么。
- 回归：新增/更新的用例名。
- 验证：门禁级别 + 数字 + 回执路径。
- 回滚：回滚动作 + 不得回退的守卫。
- 备注：可选自由正文（bodyExtra）。
````

## 门禁怎么判

`verify-l12-doc-ledger.ps1` 对 id 日期 ≥ 2026-11-23 的条目逐条检查上表必填标签行；
缺一个就非零退出并在错误里点名条目 id 与缺失字段。行为本身由 `scripts/test-l12-doc-ledger-schema.ps1`
（夹具驱动）看住：历史条目缺字段必须通过、新条目缺字段必须红。
