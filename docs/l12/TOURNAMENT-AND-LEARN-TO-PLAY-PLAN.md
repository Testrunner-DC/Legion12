# 赛事中心与学习游玩规划

## 赛事中心

赛事中心位于“大厅”下方，承担公开赛事发现、赛事代码加入、玩家办赛、报名、轮次和对阵管理。

当前原型已完成本地赛事建立、检索、报名、开赛、首轮配对与结束流程；正式上线前仍需把赛事、人员和轮次数据迁移到服务器账户体系。

### 角色和对局权限

- 玩家：只可看到自己选择的天灾、随机公开的天灾和已经揭示的天灾。
- 普通观战者：可跟随天灾禁用、公开、选用流程，但不可看到双方尚未揭示的私有选择。
- 主办者、裁判：经服务器核验赛事工作人员身份后，可使用全知裁判快照查看本局全部天灾。
- 普通观战请求不得携带一个可自行声明的 `referee` 标志来获得全知信息；裁判权限必须来自赛事和账户授权记录。

后续阶段包括：服务器赛事库、裁判任命、报名审核、瑞士轮与淘汰赛编排、桌号与房间绑定、结果上报与复核、审计记录、赛事回放和裁判介入工具。

## 学习游玩

学习游玩入口未来放在规则页面下方，采用类似《炉石传说》新手教学的逐步引导流程，但严格使用《十二军团》原始名词和规则。

建议章节顺序：

1. 主宰、士气、前排和后排。
2. 回合阶段、支付费用和打出军团。
3. 活跃、休整、位移、近战与远程进攻。
4. 抵挡、支援和主宰受伤。
5. 主动战术、反击战术、响应与堆叠。
6. 天灾值、天灾触发和完整准备流程。
7. 阵营效果、圣物和特殊区域。
8. 一场带提示、撤销与复盘的完整教学对局。

每一课应使用锁定牌库和确定性脚本，分为“演示—玩家操作—即时解释—错误纠正—目标复盘”，并记录操作事件，便于测试和复盘。该功能排在规则内核、S1/S2 卡效验收和赛事基础数据服务稳定之后。

## GrandUMI 新网络框架学习（待处理）

在当前规则内核、权威快照和基础联网稳定后，对 GrandUMI 最近更新的网络框架做一次独立差异审计。该任务位于赛事正式服、断线重连和观战深化之前，不直接复制实现，先形成可验证的迁移方案。

审计范围：

1. 房间创建、加入、准备、离开、销毁与恢复的完整生命周期。
2. 断线重连、原座位恢复、会话令牌、重复连接和多端登录处理。
3. 玩家、普通观战者、赛事主办者和裁判的权威快照及信息隔离。
4. 命令序号、幂等、重复消息、乱序消息、断点补帧和状态哈希校验。
5. 协议版本协商、旧客户端兼容、服务端滚动升级和错误恢复。
6. 对局事件持久化、回放复用、网络诊断指标与自动化故障测试。

交付物应包括：GrandUMI 新旧框架差异表、十二军团当前协议差距、可复用部分、不可照搬的规则差异、分阶段迁移步骤、回滚方案和对应测试矩阵。
