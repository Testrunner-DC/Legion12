## 本轮评审结论

实施状态补充：Main 已按限定方案实现；本地完整矩阵最近一次 36 组、331 项通过，后续独立复核又用真实不同主宰选择复现焦点竞争三红，已以稳定编辑行修正并重验。面板滚动、账号/异步响应隔离、选卡真实图片、取消初焦点和弹框键盘模型均纳入回归。手机宽度小于 600 时暂按两列保证控制可读性，较宽竖屏实际支持小/中/大卡图偏好四/三/两列；原平板选择器被 Vue scoped 编译吞后缀的四红保留并已修正。当前 Edge 不支持非零刘海安全区注入，不能计为通过；真实 Safari/微信输入法依然须按下文清单试用。独立复核及最终门禁没有结束前，本文不标最终收口或可部署。

建议保留原编辑器状态与保存流程，优先评审编辑器限定的自然竖屏，而不是继续缩小整个横向画布。依据是本项目已实测的旋转、短屏失焦跳变与弹框越界，不是同类游戏的流行程度。

| 决策项 | 本轮意见 | 仍需取得的证据 |
| --- | --- | --- |
| 整页横向画布缩放 | 不作为自然竖屏的主要方案 | 真机当前版操作成本，以及限定方案是否改善而非引入新问题 |
| 编辑器单一状态与原保存路径 | 必须保留 | 后续实现的刷新、草稿、离开保护和稳定 ID 等价证据 |
| 卡池密度 | 窄屏两列为首个试验值，不锁死所有手机两列 | 实际卡图可读性、按钮误触与较宽屏三至四列比较 |
| 详情与已保存牌库 | 复用可滚动抽屉/弹框，不让长列表挤占详情 | iOS 安全区、键盘、末项和关闭按钮可达性 |
| 输入与横竖切换 | 输入期间稳定布局，不重新挂载编辑器 | Safari 配合微信输入法的候选、失焦、工具栏和旋转试用 |

研究结论是可进入限定实施；用户随后已批准开始。完整截图对照和真机试用仍保留未验证标记，不把产品实施验收门槛提前判为通过。

## 改造目标与保留内容

竖屏编辑器应让玩家直接完成命名、筛选、查看详情、加减卡、保存与返回，不需要把手机横过来，也不需要横向寻找操作。它不是另做一套编辑器：状态、卡池、稳定牌库 ID、草稿、保存、合法性与权限均复用原实现。

保留全部现有功能，包括主宰、主牌库、额外卡牌和备选区，统计、起手分析、对局建议、公开内容、生成牌库图、新建、另存、删除及异画权限。公开牌库还原原画、自有权限异画可用、未完成构筑仅能暂存草稿等边界不变。

桌面保留现有三栏和左侧详情约 5/7、已保存约 2/7 的分配。对战、沙盒、观战及回放不在本次改造范围，不得借编辑器研究改动这些页面的逻辑横向画布。

## P4 边界与方向策略

当前 `/deck-editor` 显式加入 `landscapeCanvas`，`App.vue` 决定逻辑画布及缩放策略，`mobileViewport.ts` 管理可视区和共享坐标。编辑器已有 `mobilePane`、详情抽屉、已保存弹框、离开保护和账号草稿，不应复制它们。

拟在编辑器这一条显式路由增加可审查的自适应策略，而不是全局关闭逻辑画布。地址、`deck` 和 `returnTo` 等查询协议不变；按实际可用宽高和明确的玩家偏好决定编辑器模式，不读设备身份或物理方向传感器。

- 窄而高的可用区域采用自然竖屏；宽屏及可用横屏保持原模式。最终阈值从尺寸连续扫描得出，不按某个手机型号硬编码。
- 输入期间保留进入输入前的布局模式；键盘的高度变化只能调整可见区域、滚动和输入可达性，不能触发旋转或重挂载编辑器。
- 横竖切换只重排同一个编辑器实例，不重载牌库，不清空筛选、数量、草稿或未保存状态。需要特别防止 App 的条件分支更换容器时卸载组件。
- 共享 `visibleViewport`、坐标换算和对战 Teleport 的既有契约保持。若确需扩展，只提供编辑器限定入口，并补充原对战调用者的等价回归，不调整其默认行为。

这是一项已批准的限定 P4 产品变更。不会修改架构锁来绕过门禁；按本文目标、原状态迁移方式与退出条件实施。

## 竖屏工作区布局

| 区域 | 拟呈现方式 | 必须保留的行为 |
| --- | --- | --- |
| 操作头 | 名称、张数、保存直接可见；新建和其他次要动作收进已有菜单 | 不在键盘打开时占满屏幕；菜单打开后仍可关闭并访问全部动作 |
| 工作区导航 | 牌库、牌表、统计/起手；已保存用按钮打开列表 | 不以永久展示桌面三栏换取手机入口；公开内容仅在适用时显示 |
| 卡池 | 筛选与结果相邻；手机先评估两列，较宽竖屏评估三至四列 | 卡图保持比例且完整；加减、备选与详情不得互相误触 |
| 卡牌详情 | 复用详情内容的可滚动抽屉 | 效果文本可读、关闭可达；退出后恢复原卡池位置 |
| 已保存牌库 | 复用列表弹框；仅列表滚动 | 长名称、18 项以上、最后一项与关闭按钮都可访问；切换走原未保存保护 |
| 牌表与分析 | 单工作区内自然纵向呈现 | 主宰摘要、数量与分区完整；费用曲线、选卡组件、对局建议仍复用既有组件 |

主体只指定一个纵向滚动容器；打开弹框时主体停止接收滚动，弹框内容使用自己的纵向滚动。安全区、浏览器工具栏和键盘变化均要计入可访问区域。不得靠缩小整页、隐藏功能或裁切卡图解决溢出。

## 分阶段实施顺序

1. **先完成真机当前版取证。** 确认实际系统、浏览器、输入法，使用自己的测试牌库完成下表；与浏览器研究逐项对照。暂未取得设备时继续准备资料，不伪称通过。
2. **确认限定 P4 方案。** 确定只改编辑器的方向策略、稳定组件容器及 scoped 布局；列明实际文件租约、尺寸阈值和回退开关，取得实施批准后才改生产源码。
3. **先实现最小骨架。** 同一个状态源、原保存路径、自然竖屏及稳定输入模式，先验刷新、离开和切换；不同时改造卡效、存储或对战。
4. **补齐全部入口。** 详情、已保存、异画、删除、生成牌库图、对局建议、公开提交、统计和起手分析逐项验收，再调整卡图密度与操作头。
5. **独立对抗验收。** 真机中文输入、浏览器尺寸连续扫描、横屏/桌面回归和完整既有门禁均完成；Main 独立复核后才收口及同步。本轮没有部署步骤。

已确认组合：系统 `iOS，版本待填`；浏览器 `Safari，版本待填`；输入法 `微信输入法，版本待填`；手机型号/屏幕 `待填`；页面版本 `待填`；测试时间 `待填`。记录真实完成结果、误触、遮挡、滚动恢复和必要截图，不采用自动化耗时冒充人类操作时间。

优先在已可访问的当前版本使用自有测试牌库试用，无需安装额外系统或开放本机端口。Safari 竖屏命名时分别记录中文候选栏出现、候选确认、点击搜索框转移焦点、收起键盘和浏览器工具栏变化；每一步核对输入内容、布局方向与保存入口。随后用 Safari 普通返回和边缘返回手势检查离开保护，确认继续编辑不丢内容。横竖切换分别在键盘打开和收起时记录，不依据模拟 `visualViewport` 值代替实际观察。

## 独立验收矩阵

浏览器覆盖至少 320×568、360×640、390×844、430×932、768×1024，以及 667×375、844×390、1024×768、1366×768、1920×1080。针对最终阈值额外测试上下各 1px 和连续缩放。键盘高度模型与真实输入法分别记录，不相互替代。

测试还要组合长名称、长效果、空牌库、非法构筑、完整合法构筑、18 项以上列表、三种卡图大小偏好、长操作提示、已发布与未发布内容、权限异画与无权限账号。模拟网络/存储失败只在隔离环境执行；不得用真实个人牌库注入故障。

浏览器需给出元素边界和实际点击/触屏证据，关键动作及卡图不能裁切，弹框关闭不能越界，不出现为主要流程服务的横向滚动。交互失败、数据丢失和权限泄露均为阻断，不能以截图外观合格抵消。

实施后检查既有 B1 草稿、B2 稳定 ID 与原保存合法性、返回我的牌库路径及统一 UI/主题/卡图/架构保护；按最终变化选择 Focused、Batch 和干净提交级 Release。不为文档准备重复运行全卡测试。

## 回退与退出条件

出现内容丢失、保存或稳定 ID 改变、未保存保护失效、关键动作不可访问、权限异画泄露、卡图裁切、弹框越界或横屏/桌面退化，停止该实施批并保留失败证据。

回退只恢复本批编辑器方向策略、组件容器与限定布局；不覆盖数据库、不删除草稿、不撤销其他已验收卡效或平台成果。旧横向布局可以作为暂时退出方式，但其已证实的可用性问题不能随回退被标成解决。

最终收口需要：实际生产实现和源绑定证据、完整具名功能验收、真实手机输入结果、Main 独立复核与门禁通过。当前生产实施中；真机与部署均未完成。能够继续本地及浏览器验收，但不能据此将真实输入法试用标为通过。
