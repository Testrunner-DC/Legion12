# 十二军团 FAQ 信息架构与增补路线

## 本轮采用的范例范围

参考《ONE PIECE CARD GAME》官方 Q&A 页的网页结构，不移植其游戏规则。十二军团规则中心采用以下层级：

1. 最新规则书 / FAQ 两个一级入口。
2. FAQ 内分“常见问题 / 单卡问答”。
3. 常见问题支持关键词搜索、主题分类、常用关键词、结果计数、全部展开与全部收起。
4. 单卡问答支持卡名与全文检索；卡牌档案补齐统一卡号与收录季映射后，再加入按 S1、S2、后续产品分组。
5. 每条问答保留来源原文，不因网页分类而改写术语或裁定。

## 当前资料能直接承载的内容

- 已导入规则书文字块，可按章节与原文搜索。
- 已导入当前数据文件中的 56 条 FAQ、勘误与卡牌调整资料。
- 已能按“准备与基本规则、进攻与战斗、效果与响应、区域与状态、单卡裁定与勘误”做检索分类。
- 当前 FAQ 数据没有统一的卡号、收录季、发布日期字段，因此页面明确显示缺口，不猜测数据。

## 与十二军团相似、但当前 FAQ 尚未形成通用裁定的主题

以下只列需要补写的题目方向，不代表裁定答案。答案必须以十二军团规则书、FAQ 原始资料或设计者确认结果为准。

| 优先级 | 待补主题 | 为什么需要通用 FAQ |
| --- | --- | --- |
| P0 | “至多 / 可以”是否允许选择 0 个目标 | 直接影响可选效果、目标预声明与费用支付合法性 |
| P0 | 没有合法目标时能否发动，费用是否仍支付 | 需要与 `PendingActivation` 的预声明、校验、支付、入栈顺序一致 |
| P0 | 效果来源离场后，已生成的当回合效果是否继续 | 当前已有个别单卡案例，缺少可复用的总则 |
| P0 | 同一时点多个触发如何排序 | 应与 `TriggerBatch` 的回合玩家批次、对手批次和拥有者排序一致 |
| P0 | 区域移动后，原区域获得的修正和状态如何处理 | 需要覆盖回手、入墓、入牌库、移出游戏和再次登场 |
| P0 | 进攻方或进攻目标在战斗中离开合法区域 | 当前有“进攻目标丢失”案例，仍缺统一的战斗终止节点说明 |
| P1 | 兵力、费用等数值能否低于 0，以及显示值和计算值 | 应与 `DerivedStats` 的设定值、持续修正与当回合修正顺序统一 |
| P1 | “每回合 1 次”是按卡牌实例还是同名卡共享 | 多张同名持续物或军团同时存在时需要明确 |
| P1 | “阵亡 / 置入墓地 / 弃置 / 移出游戏”的差异 | 关系到阵亡时、离场时、代替效果与陵墓守卫等例外 |
| P1 | 牌库为空时的抽牌、查看、展示、检索与排序 | 应与 `LibraryOps` 的空牌库失败和部分执行规则统一 |
| P1 | 所有者与操控者在跨区域移动时分别决定什么 | 已有“不能挤掉对方反击”个案，仍需总则 |
| P1 | 同时处理与分别确认的边界 | 覆盖神之天平、双方公开天灾、双方同时弃抽等流程 |
| P2 | 隐藏信息的查看、展示、公开范围与对局记录 | 网页对战需要严格定义操作者、对手、观战者及回放的可见信息 |
| P2 | 构筑例外卡的数量与起始区域 | 陵墓守卫等“不计入通常牌库但仍有数量限制”的卡需要统一入口 |
| P2 | 卡牌文字中的“然后 / 若如此 / 剩余”如何部分执行 | 可避免法老王的庆典、花魁的馈赠等多段选择再次出现流程分歧 |

## 后续数据工作

1. 为 FAQ 增加稳定 ID、更新时间、来源、适用规则版本。
2. 为单卡问答增加卡号数组、卡名数组、收录季与关联关键词。
