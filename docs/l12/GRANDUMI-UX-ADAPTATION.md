# GrandUMI 交互框架学习与十二军团适配

## 学习方法

不把 GrandUMI 当作一张需要临摹的截图，而把它拆成四层逐项映射：

1. **信息架构**：主页、房间、牌库编辑器、卡牌档案、记录、对战分别承担什么任务，页面之间如何返回和保持选择。
2. **操作语法**：先选卡，再在卡牌附近出现动作；合法目标高亮；攻击宣言后用连线和中央对阵条固定展示攻方、守方与即时数值。
3. **反馈层级**：场上即时反馈负责“现在发生什么”，日志负责“事后能否复盘”，动画负责节奏，不让三者重复播报同一信息。
4. **底层闭环**：检查它的前端状态、网络消息、服务端校验、回放数据如何对应；借用结构，不照搬航海王规则、术语和美术。

每一项功能都按“截图观察 → 阅读对应组件/状态/协议 → 写成十二军团映射表 → 实现 → 双方视角回归”推进。截图用于确认视觉优先级，源码用于确认状态边界，十二军团规则书与 FAQ 决定最终行为。

## 日志规范

### 保留

- 回合分隔：`第 N 回合 · 玩家名回合`，使用金色横线强调。
- 玩家主动决策：出牌、进攻、位移、发动效果、响应、抵挡、支援、选项结果。
- 关键结算：阵亡、返回手牌/牌库、血量变化、天灾触发、胜负。
- 可复盘的卡牌引用：显示 `卡名`，可点击后进入左侧卡牌详情。
- 天灾值：仅显示“天灾增加/减少到 X”；触发时显示天灾名称及触发效果。

### 过滤

- 常规回合维护不写日志：阶段切换、重置、通常抽牌、通常追加士气。
- 不重复写已经由结果行表达的机械步骤。
- 不把内部堆叠 ID、位置索引或调试字段展示给玩家。

### 标签

- 出牌：青色。
- 进攻：暗红。
- 位移：蓝绿色。
- 效果发动/效果选择：紫色，但用不同明度区分“发动”和“选择”。
- 响应/反击：橙色。
- 天灾：金红色。
- 系统/胜负：灰白或金色。

标签是快速扫描入口，正文保持短句。选择类日志保留完整选项与最终选择，因为它是复盘卡效的关键证据。

## 进攻显示规范

进攻进入独立的临时视觉状态，直到抵挡、支援和响应完成：

1. 进攻军团使用当前玩家阵营色描边，并显示“进攻”角标。
2. 合法目标才显示可选边框；确定目标后目标改用对手色高亮。
3. 攻击者与目标之间绘制有方向感的曲线，不能遮挡卡名、兵力和阶段条。
4. 两个半区交界处显示中央对阵条：`目标名称 + 当前兵力 | 进攻图标 | 进攻者名称 + 当前兵力`。
5. 抵挡或支援发生后，对阵条即时更新参与卡牌和最终兵力；增减值可短暂以小标签显示。
6. 结算结束后连线与对阵条消失，结果进入精简日志。

十二军团的进攻距离、前后排、支援关系与 GrandUMI 不同，因此只复用“明确攻防关系”的表现手法，不复用其目标判定。

## 页面框架适配

- 保留 GrandUMI 的完整模块：大厅、友谊房、牌库编辑器、卡牌档案、对局记录、对战、后续设置入口。
- 保留十二军团现有黑底、红蓝对抗、粗体微软雅黑与牌垫纹理风格。
- 卡牌继续按原卡面比例展示，不使用大圆角外框。
- 牌库编辑器采用左侧筛选/已保存牌库、中间卡池、右侧牌库清单与费用曲线的三栏结构。
- 自定义牌库必须通过前端提示和服务端权威校验，才能在房间中准备。
