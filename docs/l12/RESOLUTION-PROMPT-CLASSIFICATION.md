# 结算期 Prompt 分类与棘轮

更新日期：2026-09-01

## 统计口径

- 扫描范围：`服务端WebSocket/TwelveLegions/*.cs` 中全部 `CreatePrompt(`、`BeginPendingActivation(` 与 `PushEffect(`。
- Batch 6L-B 收口后，`CreatePrompt(` 静态令牌共 135 个：其中 1 个是 `CreatePrompt` 方法定义，实际调用点 134 个。相较 6J-B 的 139 个令牌，后续公共声明迁移删除了 4 个旧调用点，其中本批删除〈雷神之锤〉主动按钮后的重复发动确认。
- `scripts/test-l12-public-trigger-declarations.ps1` 将 135 设为只降不升上限，并继续逐令牌禁止已移除的结算期公开声明回流。
- “保留调用点”不等于都能从当前权威路由到达；被 6I/6J 数据路由遮蔽的旧 resolver 单列，防止把架构债误报成当前时序 Bug。

## 防回滚边界

- 主动按钮或触发候选一旦表达发动意图，不得在 StackItem 结算中再次询问相同公开模式。
- 冒号前费用在声明提交时原子支付；效果被无效、来源离场或目标失效均不恢复。
- 公开目标与位置结算时重验，但不得改选；失效只取消对应对象或独立段。
- 合法隐藏信息不得进入入栈前候选、声明数据、对手快照或公开日志。
- 同一候选已有 `PendingActivation` 时不得重复创建；双方让过后按既有响应窗口规则收尾。
