# E4 竖屏牌库编辑器研究

2026年10月3日。浏览器研究阶段已完成；真实手机键盘试用尚未完成。本项仅研究，不修改生产路由、编辑器样式、保存逻辑或维护状态，不授权部署。

结论：现有逻辑横向画布确实增加了竖屏编辑的旋转、输入和滚动成本。隔离的自然竖屏对照能复用现有编辑器完成基本任务，值得进入独立的 P4 变更评审，但不能直接把删除路由元数据当作最终实现。短屏键盘、筛选区域高度、平板卡图密度以及所有弹框仍需要专门设计和真机验收。

## 当前布局的实际成本

### 旋转与输入方向不一致

当前组五种竖屏尺寸均启用90度画布旋转。以390×844为例，名称框在物理屏幕上的尺寸是30×170，字体12px，位置靠右，文字随画布旋转；自然竖屏组是374×40、15px、水平输入。

这是实际截图和矩形测量，不是源码推测。它意味着保持手机竖屏时需要适应旋转后的阅读与触控方向，但本次没有人类试用，不能给出具体“慢多少秒”的结论。

### 竖向滑动是否能带动卡池

在390×844和768×1024的可见卡池区域分别发送物理竖向、横向触屏滑动。自然竖屏两组竖滑均使编辑器主体从0滚到205px；横滑不产生横向滚动。当前旋转组本次四次滑动均未改变窗口或编辑器节点滚动位置。

这个结果只针对证据中明确的手势起点和长度，不等于“所有滑法都不能滚动”；当前390横向手势受到可见区域限制，只有37.32px。它足以说明不能用自动化定位后点击成功来代替自然触控可达性验收。后续需检验连续滑到最后一张、切换任务后恢复位置以及误触加减按钮。

## 键盘占屏研究

分别模拟两类几何变化：仅 `visualViewport` 高度减少300px；布局视口也减少300px。360×640与390×844、当前与自然布局各两组，共8组。输入框在缩小后继续接受研究文字，名称没有丢失。**模拟没有调用手机输入法，也没有证明实际浏览器采用其中哪种策略。**

当前360×640在缩为360×340时：聚焦期间保留旋转；失焦且视口尚未恢复时退出旋转和移动标记；视口恢复后再次旋转。390×844缩为390×544未跨过该几何条件，旋转状态没有变化。证据表明存在短屏临界尺寸下的模式跳变风险，不应只按一款高屏手机验收。

自然竖屏组没有旋转标记，也没有这种旋转跳变，但360×340截图中顶部操作区仍占据大量高度，卡池仅露出开头。因此自然竖屏并非自动解决键盘后的全部可用性问题：需保证当前输入框和就近完成操作可见，其他任务区允许正常滚动，而不是再旋转或整体缩小文字。

## 自然竖屏对照仍需治理的部分

- 320/360宽度的任务导航会换行；名称、操作、提示和导航压缩卡池可用高度。需要设计紧凑任务头，而不是只删旋转元数据。
- 768宽度仍使用两列卡图，单张卡过大。该组卡池内容约6496px高，主体滚动内容约6643px；应以卡图完整、控件易点为条件研究合理的3至4列，不直接沿用手机两列。
- 搜索在主牌库筛选区；当前基本任务先由自动化找到它。真机试用要验证玩家能否独立发现、清除和回到筛选结果。
- 当前对照只覆盖已保存选择弹框。详情、异画选择、构筑图、删除确认、对局建议、起手分析与公开提交等入口仍需完整检查。
- 桌面名称及主体主要矩形保持一致，但卡池局部样式存在差异，不能宣称桌面像素完全等价。正式方案应限定适用几何范围，并保留桌面/横屏既有布局。

## 待批准的独立 P4 实施方案

以下是建议，不是已开工产品任务。

1. **仅编辑器增加自然竖屏策略。** `/deck-editor` 地址、`deck / returnTo` 等协议不变；手机竖屏使用原生方向，横屏及宽屏保留既有布局。对战、沙盒和观战的逻辑横向画布不动。策略按当前几何与显式偏好处理，不按设备身份硬编码。
2. **一个编辑器、一个状态源。** 复用现有卡池、选择、数量、草稿与牌库存储，不能另建手机保存逻辑。不完整草稿与参赛/公开合法性依旧分开；稳定ID、账号隔离、权限异画及公开原画规则保持。
3. **单任务工作区。** 牌库命名和保存保持可发现；卡池、牌表、统计/起手、已保存选择复用现有入口。详情用可滚动抽屉，已保存用列表弹框，不把桌面三栏压成手机三窄栏。
4. **键盘与滚动有唯一归属。** 键盘出现时不切换方向；当前输入和相邻确认操作可访问。主体与弹框分别有明确滚动容器，切换页签、开关详情后恢复原卡池位置，避免页面与卡池互相抢手势。
5. **完整卡图与控件优先。** 手机先以两列为候选，较宽竖屏再按实际卡宽评估3至4列。卡图使用原比例，不能下半截裁切；详情、加减和备选操作保持现有统一组件、黑体与深色控件标准。

实施顺序建议：先提交编辑器限定的 P4 边界/退出条件，获得批准；再做最小竖屏路由策略和骨架；随后验证全部入口、保存/草稿与横竖切换；最后真机和既有宽屏/横屏回归。不能只因本研究84项流程成功就直接替换生产布局。

回滚条件：输入内容丢失、未保存保护失效、稳定ID/保存路径改变、任一关键操作不可访问、异画权限泄露、卡图裁切、弹框越界或横屏/桌面回归。退出方式只恢复编辑器原 `landscapeCanvas` 策略及本批限定样式，不回写数据库、不清除草稿、不回滚其他已验收规则任务。回退布局也不能据此把本报告指出的旧可用性问题标为解决。

## 真实手机试用与最终收口门槛

待确认实际手机系统、浏览器和输入法。至少一款常用手机完成下面具名任务；如果声称支持 Android 与 iOS，两类都必须有真实结果，不能拿桌面浏览器仿真替代。

1. 竖屏打开自己的牌库，中文命名，完成候选选择、修改最后一个字、收起键盘；名称、焦点和方向稳定。
2. 搜索中文卡名并设置费用，清除搜索；筛选输入、键盘和原生选择器可读，结果正确。
3. 连续竖滑至卡池最后一张，增减指定卡，开关详情后回到原位置；无误点、无横向寻路。
4. 暂存后刷新恢复；切换账号不看见前一账号草稿，主动丢弃能清除对应草稿。存储失败不谎称已保存。
5. 打开18份或更多已保存牌库，滑到最后一项选择、关闭，再验证详情可用；列表和关闭按钮都不能越界。
6. 在未保存状态返回我的牌库，分别选择继续编辑和离开；浏览器返回、刷新、旋转、键盘关闭也检查。
7. 横屏及桌面回归：比例、三栏5/7详情分配、快捷加减、所有弹框、统计和保存合法性保持。
