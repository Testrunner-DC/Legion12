# 十二军团单人测试沙盒与 GM 面板

## 用途

单人测试沙盒复用正式对战的 C# 权威规则内核和实战棋盘，用于构造卡效场景、复现 Bug、验证响应与结算顺序。它不是客户端作弊开关，也不会向正式房间开放。

## 权限边界

- 仅 `createSandbox` 创建的房间被标记为沙盒。
- 服务端记录唯一的沙盒创建者会话；只有该会话收到 `gmEnabled: true`。
- GM 操作使用独立 WebSocket 消息 `gmAction`，不复用普通 `gameAction`。
- 正式房间、虚拟对手和观战者调用 `gmAction` 均被服务端拒绝。
- 把 GM 操作类型放入普通 `gameAction` 也无法绕过规则内核。
- 客户端按钮隐藏不属于安全边界；最终权限和所有状态变更均由服务端校验。

## 进入方式

1. 从大厅进入“单人测试”。
2. 选择我方牌库、测试对手牌库和天灾模式。
3. 创建沙盒后进入正式对战棋盘。
4. 使用右侧“GM”按钮或快捷键 `T` 打开/关闭面板。

## 当前指令

| 类别 | 指令 | 行为 |
| --- | --- | --- |
| 卡牌 | `addCard` | 按卡号连续加入1至20张卡到手牌、牌库顶部/底部、墓地或移出区 |
| 卡牌 | `placeCard` | 无视费用将军团置入指定阵地、打出圣物或战术；可选择是否触发卡效 |
| 卡牌 | `destroyCard` | 击杀场上军团，或将场上圣物置入墓地 |
| 状态 | `setCardState` | 将指定公开卡牌转为活跃或休整 |
| 状态 | `setTroops` | 将指定战场军团的当前显示兵力设为测试值，持续修正仍由正式派生值规则叠加 |
| 战斗 | `startAttack` | 指定任一方军团向对方主宰或军团发起进攻；距离、挑衅、进攻时效果、响应和抵挡复用正式流程 |
| 全场 | `readyAll` / `restAll` / `destroyAll` | 批量处理指定玩家的公开场面 |
| 资源 | `addMorale` / `readyMorale` / `restMorale` | 追加士气并切换士气/神力状态 |
| 牌库 | `draw` / `mill` / `shuffleLibrary` | 抽牌、从牌库弃置、洗牌 |
| 数值 | `setLife` / `setDisaster` | 设置主宰血量或当前天灾值 |
| 天灾 | `triggerDisaster` | 将天灾推至触发阈值并进入真实天灾结算 |
| 流程 | `setPhase` | 指定回合玩家并跳至天灾、重置、抽牌、士气、主要或结束阶段 |

沙盒选择“全部天灾”时会将可用普通天灾洗切后加入测试牌库；选择“随机天灾”时建立三张随机普通天灾；两种模式都固定让〈堙灭〉位于最底部。“不使用天灾”时天灾值始终不可操作。

## 记录与复现

- 创建沙盒时即建立 SQLite 对局记录。
- 双方调度、每条 GM 命令、接受/拒绝结果和对应权威快照都会持久化。
- 面板“导出本局 JSON”下载完整对局数据，可交给回放、自动测试或 Bug 报告使用。
- GM 成功动作同时写入 `[GM]` 对局事件，便于从日志定位人为构造步骤。

## 扩展约束

- 新 GM 能力必须先加入服务端 `L12GmCommand` 和 `HandleGm`，再增加前端按钮；禁止只在浏览器本地修改快照。
- 指令必须校验卡号、玩家、区域、位置和目标当前状态，并保证拒绝时无部分写入。
- 新增公共区域或资源类型时，要同步扫描普通规则入口、GM 入口、快照裁剪、SQLite 记录和回放。
- 不复刻其他游戏的生命区卡牌命令；十二军团使用主宰血量，因此提供的是数值设置。

## Grand UMI 对照结论

Grand UMI 当前 GM 面板提供连续加牌、追加/刷新咚、无费打出、全体 KO/横置和“对手领袖攻击”快捷复现场景。十二军团保留了对应源码作为可审计基线，并按本作规则映射为士气、主宰血量、天灾、阶段和六格战场操作；本作面板额外支持牌库/墓地/移出区、单卡活跃休整、洗牌与 JSON 复现。测试进攻不伪造结算结果，而是切入同一套正式进攻、响应、抵挡及伤害内核。
