# P1 对局内核契约目录

状态：2026-09-24 完成 P1 冻结与退出验收。本文描述现有边界，不授权改变卡效语义、协议或存档格式。

## 1. 冻结对象

首批黄金夹具位于 `TwelveLegions.Tests/Fixtures/architecture-p1-contracts.json`，由
`ArchitectureP1ContractFreezeTests`消费。它冻结以下可执行契约：

| 契约 | 当前所有者 | 冻结内容 |
| --- | --- | --- |
| 能力身份 | `L12AtomicAbilityIdentity`、`L12AtomicEffectCatalog` | 全池 `AbilityId`、`StructureHash`、触发、执行模型、原子顺序和呈现场景身份 |
| 内核端口 | `L12GameEngine` | 公共构造、命令写入口、GM写入口、四类接收者快照、状态序列化与状态读取表面 |
| 命令协议 | `L12Command` | 字段名称、类型与可读写性 |
| 结果投影 | `L12GameSnapshot`、`L12Prompt` | 字段名称、类型与可读写性 |
| 权威事件 | `L12ActionEvent`、`L12AuthorityEvent`、`CommandResult` | 字段名称、类型与可读写性 |
| 确定性状态 | 固定种子、固定双方预组、V2状态 | 初始完整状态、双方快照、观战/裁判快照、双方确认调度后的状态与玩家快照，以及投影/哈希/保存的初始调用顺序等价 |
| 恢复与隐私 | `RestoreCheckpoint`、接收者投影 | 检查点恢复前后状态/事件/各视角等价；对手、观战者与裁判看不到私密手牌，GM保留授权视图 |

哈希不是“实现正确”的替代品。哈希变化表示架构契约发生了变化，必须先用逐项等价证据说明原因，
再在同一个受审批次中更新夹具；不能为了让门禁变绿而直接重录。

## 2. 现有读写端口

### 权威写入口

| 入口 | 调用方 | 边界 |
| --- | --- | --- |
| `Handle(playerIndex, L12Command)` | 房间层 | 普通玩家唯一命令写入口；合法性、费用、选择、堆叠、事件、修订与胜负在同一内核事务内完成 |
| `HandleGm(L12GmCommand)` | 经房间权限校验后的沙盒 | 仅测试沙盒；不能成为普通对局或后台修改实战状态的旁路 |
| `RestoreCheckpoint(...)` | 恢复/持久化适配层 | 只恢复已校验的V2检查点；不读取数据库，不自行查账号或房间 |
| `MarkEventsPersisted(...)`、`MarkCardFactsPersisted(...)` | 持久化适配层 | 仅确认已经写出的游标，不改变规则结果 |

### 投影与内部读取（当前不全是纯读取）

| 入口 | 接收者范围 |
| --- | --- |
| `SnapshotFor(player)` | 指定玩家；只含其自己的私密信息 |
| `SnapshotForSpectator()` | 普通观战；不含双方手牌与未公开信息 |
| `SnapshotForReferee()` | 裁判；可看完整天灾信息，但仍不看双方手牌 |
| `SnapshotForGm(player)` | 授权沙盒；可查看沙盒所需的完整调试信息 |
| `SerializeFullState()`、`ComputeStateHash()` | 检查点、恢复与一致性核验；不得直接发给普通客户端 |
| `UnpersistedEvents`、卡牌事实游标、随机状态 | 持久化适配层；不得被页面或分析层用于补执行规则 |

`SnapshotForInternal()`当前会执行`ReconcilePendingActivationTransactions()`并可能增加`State.Revision`；
`SerializeFullState()`与`ComputeStateHash()`会先执行`PrepareV2ProjectionState()`。因此上表描述的是
“读取用途”，不是无副作用的纯查询契约。黄金夹具已覆盖初始状态、孤立Prompt、PendingActivation及恢复状态下
“投影优先”与“持久化优先”的最终收敛结果；保留既有事务时机，不以端口抽取名义提前或重复结算。

`State`目前仍为公开只读属性，属性返回的对象本身可变，是P1后续需要收窄的历史边界。
在替换为显式端口前，外围代码不得新增直接写入；迁移必须先证明旧新输出等价。

### 三层事务边界

| 层级 | 必须保持的顺序与结果 |
| --- | --- |
| 单命令提交 | 房间串行、请求去重、内核结算、状态/事件/回执、持久化成功或恢复最后确认状态保持一致 |
| 跨Prompt效果 | 每一步可恢复，费用和声明不会因重连/重复提交再次执行；不能用长数据库事务替代领域事务 |
| 对局结束 | 终局事件、对局事实、排位结算outbox、排行/统计投影幂等，不因重放或重试重复计入 |

上述边界是P2拆分的保留条件，不得把“效果被无效后费用不退”与“存储失败恢复最后确认状态”混为一谈。

## 3. 依赖方向审计

`scripts/test-l12-core-architecture-boundaries.ps1`扫描全部59个`L12GameEngine`局部源码并作为常规变更门禁运行：

- 内核不得依赖 HTTP/ASP.NET、WebSocket接入、房间管理、SQLite、录像写入器或文件系统；
- 历史`L12PlatformStore.AnnihilationCardId`已下沉为规则层`L12ActiveDisasterRules.AnnihilationCardId`；
- 59个内核源码对平台存储的依赖为0，门禁不再保留历史例外。

依赖目标为：

```text
接入/房间/持久化适配层 → 内核端口 → 权威状态与事件 → 接收者投影
```

反向依赖、数据库读取、HTTP对象、页面文案或分析查询不得进入内核。

## 4. 变更流程

1. 先运行黄金夹具并保存旧输出。
2. 在不改协议/存档格式的前提下引入新端口或纯读取适配器。
3. 用同一命令序列比较旧入口与新入口的命令结果、完整状态、事件序列、各接收者快照和隐藏信息。
4. 等价后才切换一个调用方；保留回退路径直到完整规则、恢复与连接验证通过。
5. 任何哈希变化必须写明变化字段、接收者、兼容策略和回滚方式。

## 5. 首批明确不做

- 不拆分 `L12GameEngine` 的写入所有权；
- 不替换 WebSocket/HTTP 协议；
- 不改变 V1/V2 存档、事件或回放格式；
- 不移动卡效结算语义，不借架构整理新增卡号旁路；
- 不把数据库、房间或账号服务注入对局内核。

## 6. 已知差异与版本边界

- `docs/HAND-ADD-PUBLICITY-AUDIT.md`登记的17组“有条件加入手牌”公开出口已全部收口。
  未预先公开的卡统一先公开再入手；已公开的卡使用不重复展示入口，静态守卫禁止条件检索重新直连底层入手方法。
- 当前版本的重连、重复提交防护、检查点恢复、写入失败恢复和回放一致性是硬门槛。
- 跨版本旧回放不要求维护旧引擎。兼容成本较高时返回“该版本已过期，回放无法生成”，
  保留已确认胜负和统计事实，不用当前规则重新补算历史结果。
- P3基于既有Journal V2、追加命令/事件、检查点、随机状态、请求去重、哈希校验和结算outbox演进，
  不重复建设第二套事件存储。
