## 当前差异与最小修改方案

1. `OfferResponse`仅枚举栈顶，`ResolveStackResponse`也锁栈顶。改为统一查询合法“响应来源实例 + 目标StackItemId”组合；选卡后有多个合法栈对象才选目标，只有一个自动绑定。不能借A的时机无效不合法的B。
2. 各 `Commit*Response` 目前立即把优先权交对方。统一为成功发动后保留本方优先权、重置连续让过计数；只有让过交棒。取消未提交的声明不代替玩家让过。
3. 同时触发已有分批系统；目前提示按“结算顺序”并反向入栈。改为明确“发动／入栈顺序”，按所选顺序入栈，逆序结算，不重建整套批次系统。
4. 复用已有 `ResponseTargetStackItemId`、持久化Prompt/Activation和请求身份校验；提交时重验选定目标、来源、费用及保护，失效不能自动改绑栈顶。

保留：天灾不提供反击战术窗口；来源离场不自动消除已发动效果；已提交费用不退回；隐藏反击牌身份与可用性不外泄；战斗分段、结算中新触发及天灾顺序不扩大。

回归须覆盖A/B连续发动、C选A或B、只有A合法、同名不同栈项、保护对象不同、让过计数、取消/目标失效/重复提交/支付中重连、同时时点双方排序和嵌套触发。

旧registry中“每响应一次交给另一方”“只能栈顶”的记录与本次规则冲突，不再将其作为新规则守卫；仍保留“资格检查和实际目标一致”的守卫。登场实体落场时机的规则文字歧义另列，不借本次核对擅改全部登场时机。
