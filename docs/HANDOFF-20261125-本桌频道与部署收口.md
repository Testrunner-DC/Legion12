## 四、必须知道的运维/契约事实（本批踩过的坑）

1. **容量预检回执不会自动作废**：`/opt/legion12-deployment/preflight-receipt.txt` 绑定上一次部署的包 sha，成功部署**不清理**，于是下一次部署的第一个包必被「预检回执已绑定其他运行包」挡住。处置：把它归档成 `preflight-receipt.retired-<日期>.txt`（附说明）后删除，让 `prepare-storage` 重写。**这是工具缺陷，正解是部署收尾时自动作废本次回执**（P2）。
2. **维护开关一律走后台 UI**：`maintenance/end` 只对**即时维护**生效（对计划维护返回 `alreadyApplied`）；计划维护在运营配置 `config.maintenance` 段，用 section revision / 平台版本 / 运营版本三种 CAS 值全 409。别再试版本拼法。
3. **Bug 关单的 `expectedVersion`** 取自 `GET /api/admin/bugs/query` 的 `platformVersion`；`GET /api/admin/bugs` 是裸数组没有该字段，`/api/admin/operations/config` 的 `version` 也不行（必 409）。
4. **Release 前必须把账本路径补齐**：`opcgpro-vue/src/` 与 `服务端WebSocket/TwelveLegions/` 下**每碰一个新文件**都要进 `release-ledger/entries`（玩家可感知 → `audience=players`，否则 internal），否则 Release 必红。本批连续三次被这条拦下。
5. **类型检查要用 `vue-tsc -b`**：`vue-tsc --noEmit` 不检查被引用子项目，会给假绿灯（本批真实踩到 `ChatScope` 扩容后通知类型未跟随）。
6. **`repo/.git` 只读**：本工作树的 git 元数据在只读的 `D:\GPT\Legion12\repo\.git` 下，`git add/commit/push` 需要放宽权限；不要先失败一次再重试。
7. **门禁会因沙箱 EPERM 假红**：`check-testrun-qa-ownership.mjs` 里 `spawnSync git` 在受限沙箱下失败，与代码无关；跑门禁需带放宽权限。
8. **`webpmux` 帧号是 1 基**：`-get frame 0` 拿到的是画布初始化图（解出来是整片噪声），必须用 `-get frame 1`；`dwebp` 不能直接吃动画文件。
9. **定位器失效先查遮挡链**：局内「打开好友功能」按钮被 `div.l12-prompt-overlay preparation initiative`（`z-index:3000`）合法覆盖——先后攻选择提示层会盖住整个界面。本批曾把它误判为玩家侧缺陷。
