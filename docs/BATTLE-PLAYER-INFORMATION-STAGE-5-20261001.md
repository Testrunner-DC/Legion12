## 自动核查的事实边界

- `BattlePlayerUnderstandingScenarioTests` 通过真实引擎命令与 `SnapshotFor(0/1/Spectator/Referee)` 生成调度、梅林主动效果、已付费用、所选目标、双方响应、被无效、目标离场后的重连与未完成、盖伏目标等接收者快照；另外核对历史目标冻结、结果状态和公开目标身份边界。测试生成的是虚构账户和卡牌实例，不含真人数据。
- `verify-battle-player-understanding-stage5.mjs` 把这些接收者快照挂载到实际 `GamePage`；另用真实引擎的乾坤阳空抽牌与隐藏抽牌轨迹挂载 `BattleEventLog`，并通过 `replayGameAt` 核对带目标事实与旧版无目标事实的回放。首轮覆盖 17 个桌面场景，以及响应、调度、无效结果、多段记录和带计时响应/结果各 5 种手机尺寸，共 47 个画面。计时状态是为了几何核查注入的合成 UI 数据；其对战快照仍来自真实引擎。检查实际文字、展开明细、可见控件和边界矩形；截图及 JSON 保存在忽略目录 `artifacts/stage5-player-understanding/`。
- 手机尺寸：430×932、390×844、320×568 竖屏；568×320、667×375 横屏；桌面 1440×900。竖屏使用产品实际旋转画布。自动检查只能证明文本被渲染、可操作与所列几何边界，不证明玩家能读懂、注意到或记住它。
- 首轮几何门禁曾报出 7 个手机画面的弹框边界与返回/投降区或计时区相交，其中 320×568 的计时响应框与计时区约交叠 106×21 像素。移动端弹框现按左侧阅读区与右侧操作坞之间的空间定宽和居中；47 个场景重跑后文本、语义和几何断言均通过、交叠 0 项。最窄 320×568、568×320 及 667×375 下，弹框与返回/投降区实测至少 9px、与计时区至少 10px。自动脚本保留最小 8px 间距回归门禁及逐场景截图、前后矩形。
- 目前已观察到响应说明中有 `Cost（已支付）` 混用英文；外围 `TOURNAMENT ROOM`、`LOADING`、`LOAD FAILED`、`MATCH TOOLS`、`DRAW REQUEST`、`PUBLIC ZONE` 尚未在本写入租约内修改。需要后续产品文案租约和针对性复核。
- 首轮没有覆盖计划要求的抵挡、支援、牌序、持续效果结束、断线连接文案、结算等全部 12 类；这些仍在待办中。格位全量双视角矩阵亦需继续补齐。主动查看墓地等私密行为不得通知对手或写对局记录，真人走查与后续回归需单独核对。
- 隐私路径复核边界：`target-selected` 事件会过滤不可公开的手牌对象，盖伏目标只保留位置；但服务端堆叠快照仍有原始 `Targets` 字段。测试中用反射强行塞入对手手牌实例可在该字段复现 ID，因此此反例**不能被当作合法玩家路径的泄露证据**，也不能据此宣称所有未来新卡天然安全。已检查当前公开响应投影和相关 `PushEffect`/权威事件入口，尚未证明合法命令能把对手私有手牌/牌库实例作为公开堆叠目标；阶段 6 锁定新卡门禁前，应完成合法路径与历史卡池的全量隐私审计。

## 真人走查执行卡

对象：3 位此前未玩过本游戏的玩家 + 3 位熟悉规则的玩家，分开记录。每人独立操作，不预先教授答案；先记录原话，再追问。每题按“操作前复述要求 / 操作后解释结果 / 仅看记录回顾过程”择一执行。应保存所见版本、设备尺寸、视角、截图编号、时间、原话、实际操作、答题结果和访谈者；不得记录真实私密手牌内容。题目中的「我方／对方」必须跟随受试者视角，格位写作「我方前排左格」等，不使用规则中不存在的第一、第二格。

| 编号与场景 | 任务 | 关键事实标准答案 |
| --- | --- | --- |
| 01 调度 | 操作前说出点击保留或换牌会发生什么 | 未选牌即保留全部；所选起始手牌换成等量新牌；提交前知道所选数量 |
| 02 支付与响应 | 看梅林响应框，说出现在能做什么、费用是否已经发生 | 可选合法响应或不响应；1 符文与休整已支付；后续无效不等于返还费用 |
| 03 同名与格位 | 从双方视角指出声明对象，不看内部 ID | 明确哪一方、前后排、左中右格和卡名；不得把另一张同名卡当目标 |
| 04 被无效 | 操作后解释源效果与费用 | 效果被无效，没有按声明成功；已支付费用仍保留 |
| 05 目标失效与恢复 | 重连后解释原目标和实际结果 | 原先声明的对象不自动改选；离场后效果未能完成；重连不改变历史声明 |
| 06 多段部分完成 | 只看乾坤阳记录回顾 | 一段跳过、一段完成；实际抽到 1 张；不能把整项说成全部成功或全部失败 |
| 07 抵挡 | 在抵挡提示前复述可选项，结束后看记录 | 谁抵挡、哪个对象/伤害被处理、成功或未完成，以真实记录为准 |
| 08 支援 | 在支援提示前复述行动，结束后看记录 | 谁支援、作用对象、是否实际生效；不把待选择写成已生效 |
| 09 牌序 | 完成牌序操作并只看记录回顾 | 哪些是已公开事实、哪些是私有顺序；对手不能从记录推断私有牌序 |
| 10 持续效果结束 | 看到过期记录后解释状态 | 指出效果何时结束、对象之后是否仍有加成；不能把过期说成被无效 |
| 11 断线、返回、投降 | 看对应提示说出后果与当前状态 | 分清连接恢复、返回大厅与投降；不可将返回操作理解为自动投降 |
| 12 结算及隐私查看 | 只看记录回顾胜负与一次主动墓地查看 | 胜负与实际结果可回顾；玩家主动查看墓地不产生对手通知或对局记录 |

题 01–06 有现成首轮自动轨迹或页面证据；题 07–12 在实施真人走查前须补真实可复现局面与对应截图。不得拿上表的标准答案当受试者发言，也不得仅凭模型判断计入真人正确率。

## 记录与判定模板

每一答题事实记录：`参与者编号｜新/熟练｜题号｜设备/视角｜所见版本/截图｜原话（逐字）｜实际操作｜标准事实点｜正确/错误/未答｜误解类型｜严重度｜修复建议｜复测版本与原话`。严重度分为 S0 隐私泄露或导致错误付费/提交/放弃，S1 误判目标/结算/记录因果，S2 可恢复的措辞迟疑，S3 纯风格意见。应先统计每位及总体关键事实正确率，再按误解类型修复、用同题或等价局面复测。

建议验收线：关键费用、提交、放弃、隐私信息零 S0；代表场景关键事实正确率至少 90%。六人走查是发现理解问题的小样本，不可称为总体玩家理解率的统计证明。当前结果栏：**真人 0/6，正确率未测，阈值未判定**。本阶段状态为“自动首轮 47 场景通过，余下场景覆盖与真人理解待补”，不能进入最终锁门禁或宣布整案完成。
