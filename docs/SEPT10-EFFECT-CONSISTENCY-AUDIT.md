## 本次发现并修复

### 始皇帝 嬴政

- 根因不是原支付函数本身，而是效果登场、GM/权威置入和重复登场等通用入口绕过了登场前支付网关，直接把击杀段放入堆叠。
- 所有登场入口现统一在 `QueueOrPushTriggeredEffect` 进入冒号前 Cost 网关。只有实际支付当前费用恰为 8 的军团后，才允许击杀、返还士气和追加士气限制入栈；没有合法支付对象只展示手牌。
- 候选和提交均读取当前费用而不是印刷费用。已选对象失效但仍有其他合法对象时重新计算候选并生成新 Prompt；旧 Prompt 作废，重复提交不能二次弃牌。来源离场或候选全部消失会安全关闭或进入未满足条件分支，不会卡死。

### 天照大神

- 第二能力的弃牌 Cost、最多两张休整士气选择、一次响应边界和前排【高天原】持续 +1000 保持为同一能力，但数值状态、展示状态和实际事件此前不是同一份权威投影。
- 现在结算建立按 `TurnSerial` 限定的持续状态，立即重算兵力，并发布准确的实际效果事件；V2 快照为受影响军团提供“本回合兵力+1000 / 天照大神”状态。
- 回归固定结算当刻、之后进入前排、前后排移动、检查点恢复/重连、整项被无效及回合结束清除，避免把一次性加值误当持续状态或只改界面不改实际数值。

### 孙悟空

- 服务端卡牌目录已是批准后的新文本，但图鉴使用的 `cards.lookup.json` 仍保留旧文本，这是此前只核对一个来源导致的遗漏。
- 图鉴 `effectText`、搜索文本和服务端 S2 目录现逐字一致。卡图架构门禁新增孙悟空专门契约，任一来源漏改都会使生产构建失败。

## 后续强制标准

1. 冒号前 Cost 必须经共享预支付事务；候选与提交使用同一当前状态谓词。
2. 冒号后的效果对象不反向成为发动费用；必发效果无对象时 `skipped`，有对象即使唯一也保留玩家选择。
3. 入栈时声明对象，逆序结算时用同一谓词重验；失效为 `failed`，不改选、不退已支付 Cost。
4. 支付或选择失败必须可取消、可安全重选或进入规则定义的替代分支；旧 Prompt 和重复命令不得再次改变状态。
5. 持续效果必须进入权威状态、快照和恢复数据，而不只是结算当刻修改一个实体或只显示文字。
6. 每次卡文变更必须同时校验服务端目录、图鉴、搜索、按钮/Prompt、实际结果、动效、日志和回放；生产构建必须执行交叉来源契约。
7. 后台卡效工作台仍排在效果一致性之后；届时结构化能力段将成为卡文、勘误、产品收录、Prompt/日志/动效文案及呈现样式的唯一来源，样式选项必须带图例或可播放范例，并遵循现有布局与设计系统。
