# 赛事中心收口边界

更新：2026-09-25

## 玩家流程

- 报名时不提交牌库；赛前签到时从账号牌库选择构筑，由服务端完整校验后形成不可变快照并锁定。
- 正式开赛只计入已完成赛前签到的玩家；每轮独立准备，已到齐桌可先开始，迟到桌进入宽限期而不阻塞其他桌。
- 新赛事对局使用与排位同源的五阶段权威计时，支持断线重连和服务重启恢复；已在运行的旧赛事保留原桌次截止时间。
- 参赛者只能进入自己的当前桌；本场主办者和裁判可观战。重连和每次操作都重新校验当前资格。

## 主办与裁判

- 主办者或全局管理员可在开赛前或进行中移除玩家，可选择同时禁止其重新报名。进行中的未完成桌会给对手记录权威胜场，被移除者不得再进入、恢复或操作该桌。
- 主办交接只能发给本场裁判或当前主办者的已接受好友，必须由接任者确认。接受时会再次校验资格；交接后旧主办者不再自动具有工作人员权限。
- 补时直接追加到对应桌的权威总时间；暂停赛事推进不会停止已经开始的对局计时。

## 不可变事实与恢复

- 赛事创建时固定已发布的规则中心版本与内容哈希；参赛牌库锁定时保留公开牌库来源版本和构筑哈希。
- 对局结束与赛果待回写事实在同一 SQLite 事务中落盘；中途失败可幂等重放，不会覆盖先到的工作人员裁决。
- 公开查看者不获得玩家移除理由、禁报状态或主办交接历史；被处置本人、指定接任者及本场工作人员只获得完成当前操作所需的最小信息。

## 验收要求

- 平台赛事全流程、全局管理、牌库快照、幂等命令、重启恢复和权限边界必须通过。
- 前端 UI 契约、资源变更推送、连接恢复、类型检查、正式／测试构建必须通过。
- 本批不单独部署；与其他在途任务一起通过最终 Release 后，再按测试服、正式服、解除维护的顺序发布。
