# 十二军团三对话指挥与分工协议

生效日期：2026-09-08。本文定义长期协作方式；具体任务状态仍以 `TASK-LEDGER.md` 为准，代码与线上状态仍须重新核实。

## 1. 指挥关系

| 工作流 | 定位 | 可以负责 | 不得自行决定 |
| --- | --- | --- | --- |
| 本对话（主对话） | 唯一指挥、集成与发布中心 | 需求澄清、规则裁定、优先级、任务拆分、后端/卡效直接开发、跨模块集成、最终验收、Git、部署、回滚、日志和 Bug 回填 | 不以分工对话的“完成”代替独立审查 |
| `L12-UI` | UI 专职执行工作流 | Vue/HTML/CSS、组件交互、响应式布局、UI 契约、前端行为测试和实际视觉证据 | 卡牌规则、服务端协议、数据库、权限、Git 与生产操作 |
| `L12-Effect` | 卡效辅助执行工作流 | 获租约后的卡效引擎/规则实现、同类全卡池扫描、确定性卡效回归 | 规则含义最终解释、UI/网络/数据库扩张、Git 与生产操作 |

主对话仍可直接修改卡效；`L12-Effect` 用于分摊边界清楚、测试成本较高或可独立收口的卡效批次，不是卡效工作的必经入口。

## 2. 何时才分工

主对话只在以下条件同时成立时向用户建议分工：

- 子任务能够独立描述和验收；
- 预计节省至少约 30% 的实际处理时间；
- 文件写入范围基本不重叠；
- 用户规则已经明确，执行者不需要反复猜测；
- 交接、复核和重新测试的成本明显低于并行收益。

以下情况不分工：小型直接修正、紧急线上故障、规则仍有歧义、高冲突公共文件、需要频繁跨 UI/引擎/数据库往返的改造。跨模块任务由主对话保留，或拆成有先后顺序的契约阶段，不并发写入。

## 3. 写入租约

分工不是“同时自由修改”。每个执行批必须由主对话发出唯一写入租约，至少包含：

```text
批次：
目标结果：
基线提交与当前脏树摘要：
允许修改文件/目录：
禁止修改及其他工作流持有文件：
规则与接口边界：
Focused/专项验收：
返回内容：精确文件、测试、未验证项、风险、是否冻结
提交/同步/部署：一律禁止，除非主对话另有明确授权
```

执行规则：

1. 同一文件同一时间只有一个写入者。
2. `AGENTS.md`、本文、`TASK-LEDGER.md`、`HANDOFF.md`、`BUGFIX-REGISTRY.md` 默认只由主对话修改。
3. `GameBoard.vue`、`L12WebSocketServer.cs`、公共模型、持久化和发布配置属于高冲突区；没有逐文件租约不得修改。
4. 需要越界时立即停止写入，保留现场并向主对话提出顺序交接，不得“顺手修复”。
5. 租约结束时先冻结文件；在主对话接受或退回之前不继续扩展。

## 4. 信息流与决策优先级

决策优先级从高到低为：

1. 用户最新明确裁定；
2. 卡牌印刷文本、规则书、FAQ及已记录设计者裁定；
3. 主对话批准的本批方案和租约；
4. 项目现有测试与实现；
5. 分工对话的推断。

出现冲突或语义不清时，分工对话不得自行选一边，必须将证据和具体问题交回主对话。插入需求默认进入队列，不会自动覆盖此前已接受任务，除非用户明确要求改优先级。

## 5. 卡效工作流程

卡效问题先由主对话验证玩家报告是否成立，并取得用户对规则含义的确认。随后由主对话决定直接处理，或把一个独立效果批租给 `L12-Effect`。

`L12-Effect` 每批必须：

- 先查修复记录和当前 diff；
- 编码失败回归或确定性场景；
- 扫描 S1/S2 全卡池中相同触发、费用、目标、区域、响应和展示模式；
- 优先修改公共根因，再迁移同类入口；
- 返回受影响卡牌全称，不使用玩家俗称代替正式名称；
- 只运行本批专项/Focused，冻结后交回主对话。

涉及卡效 UI 时，先由主对话确定服务端权威状态和展示契约，再依次交给 `L12-UI`；两个分工对话不得同时修改同一协议或组件。

## 6. UI 工作流程

`L12-UI` 获得租约后负责页面结构、响应式、交互反馈和视觉证据。需要后端数据时，只提交字段、状态和错误语义需求，由主对话决定是否实现接口。

UI 交接必须包含：

- 修改的精确组件和样式；
- 支持视口与压力场景；
- UI 契约和类型/构建结果；
- 实际截图或浏览器测量证据；
- 已知未覆盖比例或状态；
- 确认没有改变卡牌规则、支付或隐藏信息边界。

## 7. 验证去重

- 分工对话：只跑与租约对应的失败回归、专项和 Focused。
- 主对话：接收冻结交接后审查最终 diff，统一跑一次整合 Batch。
- 已授权同步或部署时：在干净提交上只跑一次 Release，并复用提交绑定产物。
- 分工对话不得各自重复运行完整 Batch/Release，除非主对话因风险证据明确要求。
- 共享缓存或构建输出被占用时，不终止其他工作流或覆盖缓存；等待所有者冻结，或使用经项目允许的隔离缓存。

## 8. 完成、发布与事故处理

分工对话只能报告“实现已冻结并交接”，不得声称整个任务已完成、已同步、已部署或后台 Bug 已解决。

只有主对话可以在完成以下事项后宣布完成：

- 精确 diff 和文件归属复核；
- 同类扫描与回归证据复核；
- 一次整合 Batch；
- UI 实际视觉或卡效确定性行为验收；
- 台账、Bug 记录、回滚边界更新。

Git 推送、生产部署、维护切换、数据库迁移、服务重启、回滚、玩家更新日志及 Bug 关闭只由主对话执行，并继续遵守各自的用户授权边界。

紧急线上故障发生时，主对话可要求两个分工对话立即冻结。生产恢复、连接、认证、隐私、并发、数据库和回放完整性全部回到单一指挥路径，避免多方同时抢修。

## 9. 标准冻结交接

```text
批次与状态：已冻结 / 被阻断
基线与当前 HEAD：
完成结果：
精确修改文件：
未触碰的共享文件：
专项/Focused 结果：
失败或未验证项：
同类扫描与受影响对象：
接口/数据/运行中对局兼容风险：
提交、同步、部署：未执行
```

主对话收到交接后可以接受、退回补充，或撤销租约改由主对话接手。任何分工结果都不自动进入发布范围。
