# 十二军团单主任务与按需分工协议

生效日期：2026-09-09。用户已批准直接落地，不安排试运行。本协议取代固定主／UI／Effect 三任务工作制；技术角色可以保留，任务不必常驻。

## 1. 默认由主任务完成

主任务负责需求、用户裁定、优先级、实现、集成、最终验收、Git、部署、回滚、更新日志及 Bug 回填，也直接执行 UI 与卡效修改。不能只派发任务并等待。

小修改、紧密耦合的 UI／服务端改造和紧急事故直接在主任务推进。后台 Bug 仍须先验证、给出方案、取得用户批准；已有批准无需重复询问。新的需求进入台账，不覆盖此前已接受任务。

L12-UI、L12-Effect 保留历史和成果，不自动启动，不承担固定审批或必经阶段。需要用户持续看图反馈、接口稳定的大型 UI 改造，可经用户要求或批准作为专项任务；Effect 仅在独立卡效批确有并行价值时使用。新建用户可见任务仍需用户明确要求。

## 2. 何时使用临时子代理

只有满足以下条件之一才委派：
- 任务边界清楚，能独立验收，且主任务同时有其他有效工作可做。
- 支付、隐藏信息、恢复、结算、数据删除等高风险修改，需要独立审查具体失败路径。

不按文件数机械委派，不要求每批走规划／开发／测试／审查流水线，不要求预测固定百分比收益。明确的检索、机械修改可用快速档；复杂测试按其所验证的语义风险选档，不能因名为“测试”而自动降档。四个可选角色的模型与推理档位以 .codex/agents 为准，主任务模型由用户设置。

默认零子代理；有价值时通常一个，确实独立才同时两个。不递归委派。项目配置限制单任务最多两个子代理；它不是跨任务全局锁。主任务还须核对所有活跃 L12 专项，跨任务最多两名代码写入者（含主任务）。同一构建输出和缓存只允许一个构建者，独立代码并行不等于并行构建。

## 3. 每次派发只交付一项有限结果

派发前记录以下简短契约，已知内容用文件引用代替全文：

```text
批次／子任务：
目标与用户已确认规则：
HEAD、工作区状态时间、允许文件当前差异或内容指纹：
允许文件／禁止文件／其他写入者：
首个可核验交付物：
完成条件与专项验证：
依赖及预算检查点：
返回：结果、精确差异、测试及其源码基线、风险、未验证项、冻结状态
```

只读任务无写租约。每个文件同一时刻只有一个写入者；租约是协作约定，并非文件系统强制锁。公共协议、共享规则、生成数据、台账及发布配置默认归主任务。子代理发现越界需求时停止该部分并返回证据，由主任务接手或重新划定范围，不反复向用户询问已授权的常规实现选择。

子代理使用 fork_turns="none" 和精简任务说明，按需读取相关裁定与文件。禁止默认复制全对话、全部日志、全部图片或全部历史台账。不要把一个小修改拆成多个层层传递的代理阶段。

## 4. 防止长期停留在分析阶段

首个交付物应当可验证，例如失败回归、已定位代码路径及证据、可审查的小补丁。期限按工作大小设定为检查点，不能以赶时间为由跳过正确性验证。

连续两次实质进度检查均无新增证据、产物或明确外部阻断时，主任务缩小范围、顺序接手或结束无收益子任务。耗时不等于失败；确有新证据时可调整检查点。避免轮询同一状态和不断扩展诊断。

接管顺序为：要求原写入者停止 → 确认正在运行的命令也已结束或安全停止 → 读取现有差异 → 释放租约 → 新写入者开始。中断通知本身不证明工具已经停止。接管者必须继续交付，不把“代理未完成”作为整个任务的结束理由。

## 5. 一次集成与有效验证

- 执行者只跑租约范围内的专项／Focused，不各自跑完整 Batch／Release。
- 主任务审查最终差异和用户可观察行为，按改动风险统一验收；普通文档／编排配置仅做相应配置检查，不因此跑游戏全套或部署。
- 测试证据记录源码提交或工作区差异指纹、命令、结果、相关环境。文件变化导致证据过期时重验受影响范围；不能复用其他人的不同源码构建产物。
- UI 仍需实际布局／交互证据；卡效仍需确定性回归及同类扫描。构建成功不能替代这些证据。
- 必要的独立审查只返回具体现象、触发条件、文件位置、严重度与覆盖范围；未发现问题不等于全面正确。普通修改不设额外审查代理。
- 所有委派执行者（含既有 UI／Effect）不得修改共享状态文档、提交、推送、部署、回滚、切换维护或关闭 Bug。只有主任务执行这些动作，并遵守本批授权。

## 6. 单一状态来源与自然交接

TASK-LEDGER 是唯一任务状态入口，区分待用户判断、已批准、实施中、已验收、已同步、已部署。BUGFIX-REGISTRY 保存技术证据，HANDOFF 只保留当前接续摘要和引用。协作细则只维护在本文，AGENTS 保留入口约束。

新增要求进入队列；未批准 Bug 保持挂起。完成声明须对应实际代码、验证及发布状态。不得将配置检查称为生产验收，不得将已停止的专项称为所有待办完成。

在完整批次收口后可以接续新的主任务，先核实工作区、未完成项和有效授权。保留旧记录供查询，不要求重新读全部历史；不自动按固定轮数新建任务。日常只记录必要验收数据，不为评估编排再建长期遥测库或要求三批试运行。
