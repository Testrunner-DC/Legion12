# 低卡顿性能架构锁

本规范是开发、Batch、Release 和 GitHub `main` 验证的强制门禁。目标不是用更高的服务器配置掩盖客户端请求放大，而是让新增功能默认保持零空闲 HTTP 轮询、单次写入和有界弱网恢复。

## 不可绕过的规则

1. 页面和组件不得自行新增固定轮询。实时变化使用已认证 WebSocket 的资源变化通知；断线兜底由统一同步器管理。
2. 业务 HTTP 必须通过 `src/l12/platform.ts` 的统一出口。静态卡牌数据、图片合成和连接诊断只允许在预算文件登记的底层模块使用 `fetch`。
3. 相同账号、方法和 URL 的 GET 必须在途合并；页面卸载后不得让迟到响应覆盖新页面。
4. 写操作必须是单飞操作。自动重试只适用于安全读取，或携带并复用同一幂等键的写入。
5. 页面首屏默认最多并行三个加载项。相关资源优先使用一个权威快照，后台次要区域按需加载。
6. WebSocket 正常且数据无变化时，登录页面每分钟周期性 HTTP 请求预算为零；隐藏标签页预算同样为零。
7. 失败时保留最后一次确认数据，不得把暂时读取失败表现成“全部离线”或空数据。

## 机器门禁

`npm run check:performance-architecture` 会解析 TypeScript 和 Vue `script`，检查：

- 新增的 `setInterval`；
- 绕过统一出口的 `fetch`；
- 页面 `Promise.all` 并行加载上限；
- 预算与临时例外的格式、有效期和陈旧项；
- 架构锁是否仍接入项目构建、分级验证和 GitHub 主线验证。

`ops/performance-budgets.json` 是默认预算和底层基础设施白名单。`ops/performance-exceptions.json` 只保存尚未迁移的精确历史债务；每项必须有负责人、原因和到期日。实现被删除或回到默认预算后，陈旧例外会让门禁失败，必须在同批删除。

## 例外治理

- 禁止目录级、通配符和永久例外。
- `allowedValue` 只能锁定当前精确上限，不能为未来预留余量。
- 预算或例外放宽必须独立审查，不得与消费该放宽的新功能在同一批静默完成。
- 到期例外直接阻断构建和发布，不允许仅修改日期续期；必须提供新证据并重新裁定。
- 对战动作、Prompt、恢复快照和心跳属于权威协议，不得为了降低计数而合并关键消息或改变顺序。

## 新功能上线验收

每个新增玩家功能至少证明：

1. WebSocket 在线、数据不变的 60 秒内没有周期性 HTTP 请求；
2. 连续变化事件被合并为每资源一个在途同步；
3. 弱网或 429 不形成无限重试；
4. 页面隐藏后停止非必要同步；
5. 快速重复点击只产生一次服务端写入；
6. 账号切换、路由切换和旧连接迟到消息不能污染当前状态。

独立 AI 对抗审查是发布前的附加检查，必须寻找重试放大、跨账号缓存、版本缺口、迟到响应和预算放宽问题；它不能替代自动门禁。

## 资源变化协议

- 服务端资源名固定为 `presence`、`friends`、`rankedIntegrity`、`alternateArtNotifications` 和 `operationsPolicy`。新增资源必须先登记消费方、通知范围和断线恢复行为。
- 每次服务进程生成唯一 `epoch`；同一 epoch 内每项资源使用单调 `revision`。客户端只接受更新版本，epoch 变化时清空旧版本表并完整同步。
- 登录和重连先返回 `resourceVersions`。`resourceChanged` 只表示缓存失效，不携带业务私有数据；可安全直接投影的数据使用具名快照消息，例如 `presenceSnapshot`。
- 账号资源必须定向发送。全局资源只允许运营策略和确有全局可见性的在线状态变化；在线状态仍须按查看者生成，不得为减少计算而广播同一份越权载荷。
- WebSocket 不可用时由连接层统一发出低频 `fallback` 信号，页面不得自行恢复定时轮询。在线状态下兜底请求预算为零；隐藏页面保持零请求。
