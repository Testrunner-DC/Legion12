# C1 新玩家大厅入口详细规划

用户最新决定：C1 与 C2 一并延期，后续建立新手教学时再处理。本稿仅作为只读调查和初步规划储备，不进入 E1／D3 本批实施或验收，也不要求用户现在决定下方选项。

本方案帮助玩家从登录、了解玩法和选择牌库走到第一次休闲对战，同时保留熟练玩家的直接操作路径。当前未实施；不新增 AI 对手、教学结算或三课教学系统，也不实施已拒绝的 B3 和 D2。

建议先统一准确命名和往返路径，再完善模式恢复与账号切换，最后加入一次性新注册引导。首次默认模式暂时维持现状，不自动选择休闲、不自动匹配。

## 当前真实流程

现行大厅为 `site/BattleHubPage.vue`，`/battle` 需要登录；`/lobby` 与 `/battle/lobby` 都重定向到它。旧 `l12/LobbyPage.vue` 没有活动路由，不作为本方案改造对象。

未登录玩家进入大厅时转到 `/me?redirect=/battle`。登录或注册成功后，完成必要账号处理，再返回原目的地。规则快速入口已存在于 `/rules?tab=quick-start`，应继续使用规则中心同页子页，不另造一套规则或教学页面。

新账号只在注册时获得当时运营配置指定的官方预组，并非长期保证有六套，也不会重新生成玩家已删除的预组。游客沙盒使用的本机预组缓存不等同于账号牌库，不能自动上传或混入登录账号。

大厅当前每次挂载默认打开公开匹配及排位。五类牌库选择分别持久化：排位、休闲、好友房、沙盒我方、沙盒对手。模式本身尚未保存，因而“记住模式”属于待批准的新行为，不是已有能力。

沙盒的真实能力是创建者控制双方、手动代行对手，并使用调试指令验证卡效。它没有自动行动的 AI 对手，结果不计入正式战绩和排位。大厅为自然响应式页面，只有沙盒进入现有逻辑横向画布。

## 玩家流程设计

| 玩家状态 | 首要呈现 | 可选动作 | 不允许发生的隐式行为 |
| --- | --- | --- | --- |
| 未登录且准备对战 | 登录后进入对战 | 登录并继续、注册并继续、返回主页 | 自动进入队列或展示可操作私人牌库 |
| 本次刚注册且没有活动对局 | 一次性第一次对战提示 | 选择官方预组、查看快速入门、切到休闲匹配 | 默认模式暗改、自动匹配、强制教学 |
| 已使用过的账号 | 原有大厅及显式选择 | 排位、休闲、好友房、测试沙盒及现有快捷入口 | 强迫经过新人提示或恢复已删除预组 |
| 已在匹配队列 | 权威队列模式与取消操作 | 查看当前牌库、取消匹配 | 用本地默认排位掩盖正在排队的休闲模式 |
| 有未开局房间 | 原有整备室 | 选牌、准备、管理房规、离开 | 新人卡抢占整备流程 |
| 有进行中对局 | 现有权威对局恢复 | 按原规则恢复对局 | 引导卡阻止重连或改变返回、离房、投降语义 |
| 当前模式没有可用牌库 | 就近说明缺少可用牌库 | 重试同步、查看官方预组、管理牌库 | 猜测同名牌库、自动复种或偷偷更改其他模式选择 |

“查看官方预组”只复用项目已有预组浏览或构筑入口。若实际配置没有可复制对象，显示明确空态，不承诺不存在的牌库。不得借该入口加入 B3 的公开复制后自动承接实战流程。

## 推荐文案

文案以玩家需要做什么为主，不解释服务器和内部实现。

- 认证说明：“新账号会获得当前可用的官方预组，不必先构筑。”
- 新人提示：“选一套官方预组，了解基本规则后即可开始。建议先体验休闲匹配，不影响排位分数。”
- 没有牌库：“暂无可用于当前模式的牌库。”下方分别提供同步重试和牌库管理入口。
- 大厅页签：“测试沙盒”；沙盒标题：“单人测试沙盒”；账号字段：“当前账号”。
- 沙盒说明：“你同时控制双方，可测试牌库和卡效。对手不会自动行动，结果不计入战绩和排位。”

需要更多说明时收进帮助区域，不在开始按钮旁重复堆积系统性语句。“开始休闲匹配”必须表示真正进入队列；“切到休闲匹配”只改变当前模式，二者不能混用。

## 四个实施批次

### 第一批 准确命名与往返路径

统一真实大厅和沙盒的命名，修正“六阵营自动加入”和“测试账号”等不准确表达。添加或复用快速入门入口。沙盒登录链接携带安全的原路返回目的地，规则阅读后提供返回大厅入口。

保留所有匹配模式、派系选择、赛事、好友房规则、观战、牌库选择与现有兼容重定向。不改默认模式、不改内核、不增加自动匹配请求。

验收为游客登录回跳、规则深链与返回、沙盒登录回跳以及现有入口保留；账号服务失败时留在认证页面并允许重试。

### 第二批 模式恢复与账号隔离

建议账号内记住最后一次显式选择的大厅模式，首次仍为排位。若已有队列，以服务端队列模式为准；若已有房间或对局，优先呈现权威活动状态。大厅不能仅恢复牌库而把模式错误重置。

账号变化时立即清空旧账号的牌库选择草稿、排位资料、弹框和新人提示，再加载新账号状态。异步回复必须绑定账号代次，旧账号迟到响应不得覆盖新账号。已有账号隔离的牌库存储继续使用，不另建名称推断路径。

验收为刷新恢复排位和休闲队列、取消后留在正确模式、账号 A 切换 B、接口迟到响应、断线重连和已删除牌库。不改现有对局退出语义。

### 第三批 一次性新注册辅助

只依据“本次注册成功后进入大厅”的明确状态展示提示，用完清除；不根据本赛季零场次、近期统计或创建时间猜测新玩家。引导仅有三个动作，不遮住当前队列、房间或恢复对局。

查看规则、选择预组、切换休闲都由玩家显式点击。选择器取消不保存，查看规则不自动入队，关闭提示后仍能使用完整大厅。

首次先采用一次性路由状态，不增加账号持久化字段。若以后要求跨设备记住教学进度，另行批准账号引导数据模型。

### 第四批 多端与异常收口

完成真实任务试用和自动浏览器矩阵。截图之外记录按钮命中、焦点顺序、取消副作用、返回路径与状态恢复；不能仅以构建通过判定新人路径可用。

大厅继续自然响应，不强制手机横屏。沙盒继续原有显式逻辑横向画布和抽屉，不把桌面表单缩成不可读的手机页面。

## 异常和安全边界

- 登录失败或身份超时：保留安全目的地与输入，不能先给出可操作大厅。强制改名和改密流程继续优先。
- 牌库、目录或规则读取失败：对应操作明确不可用并提供重试，不能用游客缓存冒充已同步账号牌库。
- WebSocket 断线：不能重复建立房间或入队；重连后依据权威队列、房间和对局，不猜本地状态。
- 维护期间：继续使用现有入场策略，不让新人快捷动作绕过维护或模式资格校验。
- 选择或派系变更取消：保持原来的已确认选择，不写入半成品。好友房准备后不可换牌的约束不变。
- 浏览器返回：保留现有活动对局恢复。普通对局返回大厅不等于投降或离房，本方案不暗改。
- 账号切换：房间、对局、队列和页面私人数据走既有认证与断开流程清理，任何模式记忆均按账号隔离。

## 验收矩阵

| 检查组 | 必须覆盖的情形 | 通过条件 |
| --- | --- | --- |
| 认证与深链 | 游客直接进入三个大厅路径、登录、注册、认证失败、返回主页 | 只走真实大厅，成功返回安全目的地，失败不越权 |
| 预组与牌库 | 新账号、删除预组、无牌库、非法牌库、五个选择作用域 | 不自动复种、不混游客缓存、取消不保存、不改其他模式 |
| 活动态恢复 | 排位队列、休闲队列、匹配成功、整备室、活动对局、结束对局 | 权威状态优先，无错误模式和幽灵队列 |
| 新人提示 | 当次注册、关闭、刷新、老账号、新赛季零场次 | 不猜新人、不阻挡活动状态、不自动开始对局 |
| 沙盒 | 游客查看、登录回跳、双方牌库、天灾配置、创建失败 | 明确手控双方，原调试权限与正式统计隔离不变 |
| 故障与并发 | API 失败、目录失败、断线、重连、重复点击、旧账号迟到响应 | 保留选择，重试可用，没有重复动作或串账号 |
| 桌面与移动 | 1440和1280宽桌面；320、360、390、430宽竖屏；568×320、667×375、844×390沙盒 | 大厅不横向溢出、不强制旋转；沙盒操作、抽屉和页脚可达 |
| 键盘与弹框 | Tab、Shift Tab、Enter、Escape、打开关闭选择器 | 焦点可见、取消有效、关闭后回到触发入口 |

此外进行未读说明的具名任务试用：让不熟悉项目的使用者完成“进入休闲匹配前选好官方预组”“找到快速规则并返回”“说明沙盒对手是否自动行动”。未完成项必须记录具体卡点，不以执行者熟悉系统代替新玩家证据。

## 请用户决定的范围

1. 模式记忆：推荐记住账号最后一次显式模式，首次仍为排位；也可完全维持每次排位。首次默认休闲是第三种独立产品选择，本方案不默认批准。
2. 新人识别：推荐只识别当次注册返回；跨设备长期引导须另建已批准的账号状态，不使用近期统计猜测。
3. 沙盒访问：推荐保持未登录可看配置、创建时需要登录；所有登录入口补返回路径，不扩大创建权限。
4. 实施节奏：推荐先批准第一、第二批，再验收第三批的实际文案和密度。可只选择命名及状态恢复，不必同时实施新人提示。
