# 自适应布局根治目标

## 目标

对战与牌库编辑不再依赖设备名称、触摸能力或手机物理横屏。系统仅根据浏览器实际可用画面判断是否旋转逻辑画布、是否采用移动布局，并允许玩家在设置中覆盖移动布局选择。宽屏与移动布局使用独立结构出口，但共享卡牌、文字和间距的比例规则。

## 不可回退约束

1. “画布是否旋转”与“是否使用移动布局”是两项独立决定。设置中的移动布局选择不得触发或放宽旋转条件。
2. 自动模式读取 `visualViewport` 扣除安全区后的宽高；输入法打开期间冻结当前模式，避免页面跳变。
3. 宽屏结构不通过移动端媒体样式覆盖；移动端结构只由 `mobileLandscapeViewport` 出口启用。
4. 卡牌上的费用、兵力与天灾等级以卡牌容器自身宽度连续缩放，不再按机型写多个固定字号。
5. 对战桌文字随整体缩放缓和变小，不使用完全反向补偿把小画面文字放大到侵入卡图或容器。
6. 同类含卡图区域共用一套卡牌长宽比与局部信息令牌；主宰、圣物、军团、牌库、墓地不得分别任意拉伸。
7. 安全区、弹框、最小化入口、动态操作栏和手牌滚动必须使用逻辑画布坐标；所有可操作元素必须完整落在可视区内。
8. 每次修改必须同时通过桌面宽屏基线、移动端弹性视口、自动旋转、实际横屏和设置覆盖测试。

## 当前落地（第一批）

- 设置新增“移动布局”：自动适配、始终启用、使用宽屏布局；偏好同时写入本地与玩家账号。
- 自动判定、设置覆盖与画布旋转拆分，强制移动布局不会使横屏阈值变宽。
- `CardTile` 建立卡牌局部容器令牌，费用、兵力、天灾值及边距随卡宽连续缩放。
- 对战桌及侧置详情的语义字号从完全反向补偿改为平方根缓和补偿，缩小画面时保持层级但不再等物理字号硬撑。
- 移动天灾信息固定为当前天灾卡图、当前天灾值、本局四枚天灾圆图三段；当前天灾卡图点击仍可进入统一卡牌详情。
- Vite 开发、构建与移动验收改用 runner 配置加载器及工作区缓存，避免共享依赖目录的临时文件锁反复阻塞验证。

## 当前落地（第二批：逻辑几何收口）

- 左侧纵列改为单一配额模型：详情展开按钮、对手额外区、当前天灾卡图、当前天灾值、本局天灾圆图和我方额外区按顺序占位；固定浮层按钮同时在布局内保留等高占位，不再与天灾内容叠放。
- 主宰、圣物、战场卡、战场格、牌库/墓地、资源区、手牌、右侧操作列和卡牌数值字号全部从逻辑视口令牌取值；删除按物理屏幕高度区分手机/平板的旧分支。
- 相同的逻辑 `844×390` 画布，无论来自真实横屏 `844×390`，还是竖屏 `390×844` 自动旋转，关键区域宽高与卡牌数值字号误差必须分别不超过 `1px` 与 `0.1px`。
- 左侧纵列增加双方各三张额外区卡牌的压力场景，并在真实横屏、竖屏自动旋转两种入口同时验证安全区、顺序、无侵入和尺寸一致性。
- 全局几何门禁继续覆盖左栏/中央/右栏、上下双方战场/手牌，以及每方主宰圣物区/六格战场/牌堆/士气区；所有大区必须相互分离且子区不得越出所属容器。卡牌宽度方程显式保留内部边框和组间间隔，避免中尺寸4:3画布出现居中后两侧同时溢出。
- 移动按钮文字优先单行，空间不足时使用均衡换行；“返回大厅”使用确定的 `2+2` 两行结构并以按钮中心线对齐。其他操作按钮统一启用均衡换行，禁止四字文案出现 `3+1` 的孤字布局。
- 四个战场功能组的间距由玩家战场实际宽度反算，并限制在 `2px` 到 `1.5` 张卡宽之间；窄画面不得越界，宽画面不得整体缩在中央或为铺满而拉出过大断层。
- 路由按钮、GM入口和GM面板都使用逻辑安全视口坐标，顶部刘海/灵动岛、左右圆角及底部指示条不会再被当成可用区域。

## 后续阶段

- 第三批对战矩阵已建立并继续扩充：覆盖无牌/满场/满手牌/五符文/双方额外区/计时/全部现有Prompt与卡面动画；本轮再加入多状态/多关键词及选中卡牌后动态操作栏，固定状态截图增至555张，另有48张弹框、18张安全区、32组随机连续尺寸和桌面3档隔离验收。

## 当前落地（布局内核隔离）

- 对战页不再自行读取视口并分别维护缩放监听；`battleViewportLayout.ts` 成为唯一的对战舞台尺寸出口，集中处理紧凑判定、桌面等比缩放、GM侧栏预留和移动逻辑画布策略。
- 移动模式与桌面缩放在内核中是两个明确分支：移动结构始终在已经解析的逻辑画布中以 `scale=1` 工作，内部组件读取连续令牌；桌面结构仅缩放既有2048/2304设计舞台，不读取移动尺寸公式。
- 对战根节点显式暴露 `data-l12-battle-layout="mobile|desktop"`，用于浏览器验收和后续结构拆分；短桌面即使属于紧凑画面也仍标记为桌面，防止“窗口矮”等同于“手机”。
- 常规UI门禁新增布局内核数值测试；浏览器矩阵继续验证3档桌面、7档移动与11组自动旋转/实际横屏视口。下一步是在不改变计算结果的前提下，将 `GameBoard.vue` 中连续的移动样式段迁至独立样式模块，随后再删除被最终令牌覆盖的历史规则。
