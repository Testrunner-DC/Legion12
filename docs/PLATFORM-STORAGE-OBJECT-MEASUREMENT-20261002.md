## 测量定义

- 测量器仅能由友元测试／基准程序集显式开启；没有活动 scope 时只多一次 `AsyncLocal` 空值判断。它没有 HTTP 入口，不改变事务、SQL、镜像或错误处理。
- 已安装的 SQLitePCLRaw `sqlite3_profile` 在每条语句完成后回调。测量器只在内存中把未展开 SQL 归类为 `SELECT/INSERT/UPDATE/DELETE` 及牌库／审计／平台／schema 域，立即丢弃原文，不记录绑定值、牌表或账号内容。
- 每条 DML 后用 `sqlite3_changes` 统计直接影响行；提交时用 `sqlite3_total_changes` 记录含触发器和外键动作的连接累计影响行。基准报告使用后者作为 `InclusiveAffectedRows`。
- `SQLITE_DBSTATUS_CACHE_WRITE` 在 WAL 模式下返回该连接写入 WAL 的脏页数。报告的 `SqlitePagePayloadBytes` 是 `页数 × PRAGMA page_size`，是 SQLite 报告的 WAL **页正文**字节，不含每帧 24 字节头、WAL 文件头、同步调用、文件系统日志、缓存或块设备写放大，不能称为主机物理写字节。
- `MirrorBytesWritten` 是每次成功原子替换 JSON 兼容镜像时写入字符串的精确 UTF-8 字节数。最终数据库／WAL／镜像文件大小另列，不能与累计写入量混用。
- 每个轴、档位、重复中的登录、保存、点赞、后台审计分别使用独立合成库，消除了 F1 中前序登录审计增长污染后序保存的问题。每种操作内部仍顺序执行 100 次，保留该操作自身真实的会话或审计增长。

单变量固定基线为 50 账号、200 私人牌库、20 公开版、10 赛事牌库引用、1 种构筑正文。账号轴为 `10/50/150/500`，私人牌库行为 `20/200/1200`，公开版为 `5/20/60/250`，赛事引用为 `2/10/30/100`，正文基数为 `1/20/200`。构造完成后先读取规范化存储状态，精确断言私人行、公开行和赛事引用数量；夹具不符时失败关闭。第一次完整运行曾发现赛事兼容镜像缺少牌表而只生成赛事对象、未生成引用，已中止且不作为证据；修正并加入上述断言后从头重跑本报告。

独立审查随后发现：上述候选虽然按 `deck_id + revision` 防止同牌库覆盖，但当另一实例先写入不同牌库或非牌库平台状态时，本实例仍可能用陈旧 `_data.Version` 无条件覆盖 `platform_state`。最终候选已改为 `BEGIN IMMEDIATE` 中先执行可回滚的对象 DML，再读取最新 `storage_revision`，只有它等于本实例期望 revision 才用 `WHERE storage_revision=$expected` 显式 CAS 更新平台快照；不相等时整笔回滚、从 SQLite 重新加载完整平台状态并返回可识别的 `storage_conflict`。同牌库 revision／删除／同名冲突仍优先返回各自具体状态，不被笼统平台冲突掩盖。

## 对象写实施边界（候选已编码但默认关闭）

### 可以进入私人牌库对象级事务的调用

- B2 新接口 `CreateDeck`、`UpdateDeck(deck_id, expectedRevision)`、`DeleteDeck(deck_id, expectedRevision)`；兼容期旧 `UpsertDeck`／按名称删除只能在服务端解析出唯一稳定 ID 后进入同一路径，歧义或版本冲突失败关闭。
- 每次只写当前 `(account_id, deck_id)` 对应的 `deck_payloads`（内容寻址 `INSERT OR IGNORE`）和 `account_decks` 一行；改名在同一事务内复验账号内名称唯一约束，删除保留既有 tombstone／历史正文策略。
- 点写、平台 `storage_revision/business_version`、必要审计和镜像校验值必须仍在现有一个 SQLite 事务内形成同一提交事实。不能先点写牌库再单独 `Save()`，也不能让内存状态、规范化表和平台版本各自成功。
- 登录、会话、角色、Bug／后台等确定不改变牌库域的普通 `Save()` 在具备显式 mutation descriptor 后可跳过 `PersistDeckDomainSnapshot`；禁止靠调用栈或“通常不会改牌库”的推断跳过。

### 必须暂时保留全量或现有专用路径

- 首次 SQLite 建库、旧 JSON 导入、`EnsureAndHydrateDeckDomainStorage`、B2 稳定 ID 迁移、迁移备份、恢复演练、完整一致性修复与显式全域校验继续使用全量快照路径。
- 公开牌库发布／新版本／删除／复制绑定和赛事签到／锁牌仍保留当前全量事务，直到各自独立达到迁移门槛并有不可变版本、跨域引用和回滚合同。不得借私人牌库证据顺带迁移这两域。
- `TogglePublishedDeckLike`、浏览量和复制量已经走专用对象事务，原样保留。
- 赛季结算、身份迁移和其他从数据库最新 `platform_state` 仲裁的专用事务不得改接通用对象写入口；它们继续遵守现有 stale-revision 栅栏。

### 双读、故障注入与回退条件

1. 点写提交前在同一事务按 `(account_id,deck_id)` 读回，核对 `name_key/revision/payload_hash/bench/art/publication`；同时由现有内存对象生成期望行。任一不符整笔回滚。
2. 候选期在 D 盘合成副本运行“点写结果 vs 旧全量算法写入隔离副本”的双读比较；比较活动／删除行、正文 hash、公开来源、赛事引用、平台 revision、快照 checksum 和恢复后的 API 投影。只记录 hash／计数，不记录牌表正文。
3. 故障点至少覆盖：点写前、payload 后／account row 前、account row 后／平台快照前、审计后／commit 前、commit 后／镜像前、镜像失败、响应丢失、同 revision 并发更新、重名改名、旧标签页写入、跨账号 ID、赛季结算 stale revision。验收失败无半写、成功只一副、幂等重试不重复创建、镜像失败不伪回滚 SQLite。
4. 任一双读不一致、对象写错误率非零、恢复／旧镜像导入失败、影响行随总牌库行数重新增长，立即关闭对象写 feature flag，并由同版本程序回到已验证全量路径；保留数据库和审计，不用旧数据库快照覆盖新事实。若未来 schema 或语义使旧二进制不能安全写入，回退必须保持维护并使用兼容程序。
5. 候选验收：私人 `account_decks` 每次创建／同名更新影响 1 行、改名最多影响旧 tombstone 与新活动行共 2 行、删除影响 1 行；20→1200 行的牌库 SQL／总影响行斜率为 0，1200 行保存 P95 不高于 20 行的 1.25 倍且在本参考机不高于 15 ms；所有事务、版本、镜像和恢复专项保持通过。该数值是候选工程预算，不是玩家 SLA。
