## 二、已完成并有证据的项

### 1. 本桌频道收发（队列 `BUG-20261125-c780d4b8` / `fb70de2b`）

两处叠加缺陷，都已修：

- **服务端投递闸门**：`L12WebSocketServer.Chat.cs` 的 `FreshChatDelivery` 原来对所有非 Control 帧用「发送者↔收件人」账号对放行；本桌广播的收件人是通配 `"*"`，查账号对必然失败 → ack 与历史被静默丢弃。现在 `Scope=Table && 收件人="*"` 走 `L12ChatRuntime.TableBroadcastAdmitted`（成员 + 连接代次）。
- **客户端**：`chatResource.ts` 的 `entryConversation` 对 table 固定 peer `"*"`；`parseEntry` 允许 `scope=table && recipientId="*"` 的广播条目（否则对端把消息判为"不是发给我的"）。

证据：测试服 `5cfbdeaf` 双玩家实测 `ok:true`、`received-by-b:true`；`TableChatScopeTests` 5/5；socket 级 `ChatProtocolFeatureTests.TableBroadcastAckAndHistoryReachTheSenderThroughTheDeliveryGate`（**做过反证**：摘掉修复会红）。

## 四、本轮踩过的坑（复测必看）

1. **登录态赛事详情不是公开详情页**：`/battle/tournaments/:code` 在已验证账号下渲染 `TournamentAccountDetail.vue`（带主办管理/裁判台），`TournamentPublicDetail.vue` 只给未验证访问者。面板加错组件会"永远看不到"。
2. **测试服数据预算 512 MiB**：部署前清理 `/opt/legion12-testrun-deployment/runtime-backups` 里的旧快照（保留最新一份），否则 `dataAfter` 超限直接拒绝部署。
3. **发布资格拒绝跳过用例**：`[Fact(Skip=…)]` 会让整轮判失败，必须真绿。
4. **Tailwind 对 SFC `<style>` 行尾敏感**：用整文件重写改 SFC 会让 `Missing closing }` 报错；一律用定点 edit。
5. **`v-if`/`v-else-if` 链不能插兄弟**：往链中间插 `<section v-if>` 会把后续 `v-else-if` 挂到新元素上。
6. **正式服登录有节流**：连续调用 `/api/auth/login` 会被拒，批量写队列要逐条重读 `platformVersion` 并留间隔。
7. **staff 观战被拒的两条真实错误**：`请先离开当前房间`、`本桌对局尚未开始`（后者=room 不存在或 `room.Game is null`）。
