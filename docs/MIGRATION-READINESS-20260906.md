## 迁移前必须准备

1. **完整资产清单**：正式版本包及上一可回滚版本、数据库及排位JSON账本、进行中checkpoint/outbox/quarantine、账号/构筑/好友屏蔽/设置、赛季及历史荣誉、维护公告、文章与正文图片、首页已发布内容、上传素材、音乐、内容寻址卡图、反向代理配置与证书。运行目录不进入Git。
2. **一致性备份**：先阻止新对局并等待在途对局安全结束。冻结全部写入后取得数据库与JSON同一时点备份，记录版本、UTC时间、文件数量、大小和SHA256。SQLite活库不得只复制.db；使用备份API或可靠停服快照，保留所需WAL。分别运行数据库完整性检查、Outbox待处理数检查及称号事实回填检查。[SQLite备份API](https://www.sqlite.org/backup.html)、[WAL说明](https://www.sqlite.org/wal.html)。
3. **先做恢复演练**：在隔离环境恢复副本，用合成账号验证登录、构筑、上传媒体、首页文章、排位结算幂等、断线重连、准备60秒和正常25/4分钟时钟。旧真实数据若用于演练必须脱敏并关掉外发通知；不把真实用户会话复制进公开测试站。
4. **环境隔离**：测试服使用独立账户数据库、密钥、匿名化盐、会话/Token、上传桶或目录、日志和备份。Cookie限定各自主机，前端API/WS只指向对应环境。测试站不生成正式排行榜、荣誉或长期公告；设置醒目的测试环境标识并限制访问。
5. **容量及系统**：确认.NET运行时、Nginx、HTTPS/WebSocket升级、上传请求大小、磁盘/内存余量、文件权限、系统UTC时钟及UTC+8显示。正式/测试进程设置独立资源限额，测试故障不得拖垮正式。内容寻址卡图可只读复用，任何可变数据库或上传目录禁止共享写。
6. **密钥转移**：旧机到新机使用加密传输；凭据不打印、不入仓库、不经过聊天或本地明文文件。Windows DPAPI密文绑定当前Windows用户/设备，不能当跨服务器可解密备份。管理员账号和服务器密钥采取独立迁移/轮换计划。

## 切换顺序与放行条件

1. 先建新机、证书和路由，正式域名不切换；通过指定Host/隔离探针验收新源站。
2. 提前降低可控DNS记录TTL并等待原TTL消退；DNS缓存不会因为改记录立即全部刷新。若使用代理CDN，需确认源站切换与缓存规则。[Cloudflare迁移准备](https://developers.cloudflare.com/learning-paths/dns-best-practices/concepts/phase-2/)。
3. 旧站停止新对局，等待剩余对局安全结束，完成最终冻结和增量备份；若无法等完，必须另行确认在途对局的处理，不能自行废弃。
4. 新站恢复最终快照，数据库完整性、Outbox对账、版本和媒体哈希全部通过后才允许唯一的新站写入。
5. 切DNS/源站。旧站在缓存过渡期仅只读维护或反向代理至新站；**绝不能让两台服务器各自接受写入**。
6. 验证健康、HTTPS、WebSocket、正式版本、媒体/文章、账号设置、排位恢复与结算；观察错误率、内存、磁盘及重复结算告警。
7. 单独启用测试服并验证其数据无法进入正式环境。保留旧机和加密备份直至规定观察期结束，不在首轮成功后马上清理。

## 回滚边界

- 新站尚未接收用户写入：恢复旧版本/旧源站，使用匹配的数据备份。
- 新站已产生写入：先冻结新站并导出这些新增事实，再决定回迁或前滚修复；不能直接恢复旧快照丢掉新对局、构筑和上传内容。
- 程序回滚不等于数据库回滚。Schema兼容性、幂等账本及媒体路径要一起验证；任何失败保持维护状态，不同时开启双写。
