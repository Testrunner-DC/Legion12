# Bug 管理连接与确认流程

服务器 Bug 管理是玩家反馈、管理员审计和 Codex 修复工作的共同入口。它不授权自动修改代码或自动关闭反馈。

## 固定流程

1. 只读拉取 `new`、`confirmed` 或指定条件的反馈，同时读取每条反馈的处理时间线。
2. 先检索 `docs/BUGFIX-REGISTRY.md`，再关联页面、房间、对局 JSON 和已有回归测试。
3. 向用户提交解决方案，列明根因假设、同类型扫描范围、拟修改公共层和防回滚测试。
4. 只有用户确认后才修改代码。
5. 验证通过后，在后台追加处理记录；状态变更、优先级、负责人和摘要均由服务器记录操作人、修改前后值和时间。
6. 按仓库约定同步 GitHub。部署仍须等待用户明确指令。

关单后的本地对账复用唯一 `work-items.json`、实际终态收据与一次新鲜队列快照；阶段计数以 `bugQueue.onlineClosedThisStage` 和当前阶段记录交叉核对，不从旧发布汇总命名空间取锚点。保留先前拒绝及原字节备份，不重交已成功关单；新增反馈单列，不能用待办净变化代替实际关闭数量。

关单准备在原有一次离线自检内同时完成，不增加审批、扫描或第二条写路径：

- 明确输入是原始反馈数组还是唯一工作清单对象的 `items`；工作清单的原文哈希不能冒充API的15字段快照，后者仍绑定最新实际反馈。
- 统一schema2 proposal合同先验有界唯一ID、完整15字段/原文指纹、处置及说明。`fixed_verified`必须同时包含具名`regressionTest`、精确`fixCommit`及已独立核验的`deployedVersion`，不能等SelfTest赋值或网络阶段才发现缺字段；rejected与duplicate分别按其合同校验。
- 复用C盘既有关单执行根`post-release-adversarial-20261014/Test-ClosureProposalContract.ps1`的纯准备校验（3正/12负，零网络/写入），实际写入仍是原preview→一次CAS→独立终态读回，单个post-CAS队列快照直接复用本地对账。脚本变更先解析AST、再离线自检；派生脚本须字面替换，不让生成语言的替换元字符改变PowerShell内容。

## 有对局绑定时，先复用原记录

用户于2026-10-16持续授权Bug取证：按具体报告及其明确关联对局，复用现有管理权限提取必要诊断、检查点和故障附近命令，不再逐场重复询问。可能含私牌或个人牌库的材料仅在本地隔离处理，优先加密落盘，不展示、分享或进入公共夹具；正常登录与读取审计保留。此授权不包括无关对局、全库导出、业务数据写入、扩大可见性、部署或关闭未验证反馈。

- 固定原报告顶层 `matchId`、房间、时间、客户端／服务端／引擎版本及故障 `revision/commandSequence`，交叉核对诊断绑定；房间号可能复用，诊断摘要不等于完整检查点。
- 在既有取证授权和隐私边界内，先读 `/api/admin/matches/{matchId}` 元信息，再用已有 `/replay?limit=50` 和服务端返回的 opaque cursor 有界推进到故障附近；不导出全库、不绕过字节或命令数上限。活动非沙盒不属于已结束回放查询范围，接口404不能单独证明记录不存在；分别记录待提取、活动态、410载荷过期、409版本不兼容、413读取边界。
- 用对应原引擎、卡池、随机状态和记录时间，从合法检查点重放故障前后命令；保留 Accepted、revision、hash 校验和首个差异序号，不用新版规则反算旧结果。核实际操作方、`pendingDefense`、堆叠、Prompt、确认和区域变化；Defense中无堆叠／通用Prompt既不能单独判死锁，也不能单独判正常。
- 正常管理接口失败时，不反复从头重建分页，也不把失败当成载荷不存在。仅在已有只读取证权限内，允许按同一精确对局绑定、只读一致性事务提取最近检查点及故障邻近命令，限定时间/字节并加密；不导出全库，不借此绕过认证或扩大可见性。原版本与随机状态/逐步哈希仍须严格验证；409不兼容和410过期分别记实，不能以新规则强算或伪称原局通过。
- 权威流程通过后才转真实页面消费者：先证明合法接收者快照已到实际组件，再验可见、裁切、遮挡、禁用和原生点击／发送／确认；保持同实例生命周期，不用重新挂载掩盖问题。引擎通过不等于UI通过，相关合成场景不等于原玩家记录复现。
- 每条只保留一个取证结论：原记录复现、权威通过但UI待查、相关合成、实际确认载荷缺失／过期、版本不兼容或尚未提取，附输入SHA、版本、序号及边界后再进入既有关单流程。不能因描述短就跳过已有原记录，也不问用户是否记得玩家场景；有效同源证据继续复用。
- 私牌、账号、令牌和真实房间秘密不得进入普通反馈、共享夹具或聊天。新增取证权限或产品裁定只挂起该项，不中断其他清单；此流程本身不授权扩大提取、改留存策略或关闭未验证Bug。

## 开发电脑只读拉取

密码只从 `L12_ADMIN_PASSWORD` 环境变量或交互式安全输入读取，不写入仓库：

```powershell
$env:L12_ADMIN_PASSWORD = '<服务器管理员密码>'
powershell -ExecutionPolicy Bypass -File .\ops\windows\Get-L12BugQueue.ps1 -Status new -OutputPath D:\GPT\L12-bug-queue.json
```

可用筛选参数：`-Status`、`-Priority`、`-Search`。脚本只调用登录和 Bug 查询接口，不包含更新、关闭或删除操作。

## 管理后台闭环

- 检索：编号、标题、正文、玩家、页面、房间、对局、负责人。
- 筛选：状态与优先级。
- 关联：存在 `matchId` 时可直接打开对应对局 JSON。
- 审计：建立反馈、状态、优先级、负责人、处理摘要和追加记录均持久化。
- 历史数据：旧 Bug 没有时间线时仍可读取；第一次处理后开始保留完整历史。
