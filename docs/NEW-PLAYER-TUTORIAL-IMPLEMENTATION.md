# 十二军团教学建设与测试发布计划

用户已于2026年10月18日授权开始建设。现有“单人”位置改为教学入口；沙盒保留完整排查能力，但只允许管理员从后台进入。教学全部验收完成前不得部署正式服，阶段成果只进入测试服。

## 产品边界

- 教学目录占用现有单人入口，不增加一套平行主导航。规则中心保留阅读内容，可链接同一教学目录。
- 沙盒从公共导航移除，后台提供管理员入口；服务器验证当前账号权限，拒绝普通玩家、直接发送命令和降权后的旧连接。赛事裁判GM能力保持独立，不随沙盒收缩而取消。
- 教学只控制本人，沿原战场、选牌、防守和响应组件完成真实操作；不给玩家GM权限，不接受客户端传入种子、牌库配方或任意盘面。
- 关卡局面由受信任服务器配方建立，完成由权威命令结果确认。支付后的费用不增加教学专用撤回，重试重建本短关。
- 教学与普通房间生命周期、战绩、排位、公开统计和奖励隔离，不能只靠前端隐藏。关卡断线与重复提交不重复付款或推进。
- 初期按本人账号隔离保存本机章节进度；不新增云端进度、经济奖励或通用AI。

## 实施顺序

1. **入口与权限底座**：将公共单人入口指向教学目录，后台接入管理员沙盒；完成服务器权限与普通对局不受影响的回归。
2. **三关实操样板**：支付部署、普通移动、进攻防守。每关有一个当前目标、真实可用按钮、错误说明、结果复盘、退出和重试。
3. **测试服验证**：通过受影响本地规则、平台和前端验收后，按标准流程仅发布测试服，走真实连接和桌面／移动端全链操作。
4. **补齐基础路线**：战场识别、发动与响应、天灾、构筑、独立小局；目录、进度和重学沿同一框架接入，不复制规则实现。
5. **整体验收**：全部课程、账号切换、隐私、拒绝、重复、恢复、退出、维护及统计隔离通过后，再提交正式发布建议。未完成整体验收，不切换正式服。

## 并行安排

后端线负责受信任关卡、权限、薄教学投影、有限合法对手脚本与生命周期回归；前端线负责入口迁移、目录、引导呈现、本机进度及真实组件操作。两线先冻结最小命令和投影合同，代码文件不交叉；Main负责整合、独立复核、共享构建、记录和测试服发布。共享构建串行，最多两名代码写入者。

保留P0—P4既有出口：教学仅编排原内核命令和原接收者投影，记录仍走原Journal；训练沿已有sandbox数据隔离，不新增对战数据库格式。P4仅将原沙盒的具名横向画布资格随路由迁入后台，旧地址改为受保护跳转；不把整个后台或教学目录旋转，也不删除路由范围锁。匹配排队时须先由玩家明确取消匹配，才可创建教学，不悄悄取消或转成真人对局。

## 首片接线合同

创建使用`createTutorial`，只接收三枚课程ID和请求ID，不接收客户端牌库、种子、行动方或检查点。操作继续使用原`gameAction`；退出沿原离房确认，确认旧房已退出后才可重新创建。连接成功声明教学是否可用；服务器单一`L12_TUTORIAL_ENABLED`开关默认关闭，只在本次测试服明确开启。

房间与对局信封携带`{lessonId,version:1,stepId,status}`薄教学状态；`status`只允许`active/completed`。本人仍用普通投影，`gmEnabled=false`，不把教学元数据写进规则状态或另建规则引擎。

| 课程 | 权威步骤 |
| --- | --- |
| deploy | deploy → completed |
| move | move → completed |
| combat | attack → end-turn → defend → completed |

首片攻防允许当前合法的防守分支；完整支援与反击练习后续补齐。完成不自动跳下一关，投降不计通关。同进程断线沿现有会话恢复；服务重启后若课程上下文已失效，明确重开本短关，不用本机记录伪造恢复。

## 验收要求

| 范围 | 通过条件 |
| --- | --- |
