状态：长期目标与决策索引。2026-09-24 已完成 P0、P1、P2、P3、P4 退出验收，当前既定架构阶段已经收口。后续工作进入受现有契约保护的渐进维护，不因本文退出而自动启动新的大规模重构、同步或部署。每个变更批仍须以当时的最终候选提交重新验证。

当前基线：`origin/main`已包含P0—P3架构收口与P4所依赖的规则中心、移动自适应和桌面隔离实现。本文不把测试服或正式服的某次活动版本当作架构事实；精确主线、测试服和正式服版本分别以Git远端读回与部署回执为准。不同工作树、任务上下文和未提交文件不会自动同步。

## 一、北极星

十二军团保持**服务端权威、单局原子结算、客户端只投影状态**：

```text
玩家命令
  → 合法性与费用/选择校验
  → 单局效果堆叠、Prompt 与权威状态事务
  → 权威事件与结果状态
  → 快照、对局记录、动画、回放、后台审查的受限投影
```

卡效的唯一出口为：

```text
卡牌/规则资料 → 稳定能力身份与原子目录 → 运行时路由
→ 原子解释器或已验证组合流程 → 权威结算 → 玩家可见结果
```

详细的卡效出口约束与合入门槛见[卡效统一出口集成门槛](CARD-EFFECT-OUTLET-INTEGRATION-GATE.md)。本文件不取代该文档。

## 二、架构原则（长期不变）

1. `L12GameEngine`是单局状态的唯一写入者；浏览器、后台、回放和分析不得重新计算或补执行卡效。
2. 卡牌能力、展示场景、结算结果与公开范围必须有稳定身份；不能以文案、显示顺序或前端临时状态作规则依据。
3. 一项效果只有一个结算所有者。允许复杂组合流程，但禁止新增逐卡旁路、双重结算或前端规则副本。
4. 命令、支付、选择、响应、逆序复核、结果与恢复属于同一事务；断线、重复请求或旧 Prompt 均不得二次结算。
5. 隐藏信息按接收者投影。对手、观战者、后台审查和回放分别拥有明确可见范围，不能从日志、动画或错误提示反推出私密信息。
6. 内容规则与运营控制分层：卡牌、规则书、FAQ、禁限与赛事版本均可追溯，但运行中的对局固定其创建时的规则/运营版本。
7. 前端以领域状态和组件展示分层；网络恢复、快照核验、界面布局和业务规则不得相互偷渡职责。
8. 单体可模块化，但不以微服务化为目标。只有边界、失败模式、监控和回滚都清楚时才考虑进程或存储拆分。

## 三、目标模块边界

| 层级 | 当前核心 | 目标职责 | 不应承担 |
| --- | --- | --- | --- |
| 接入层 | `L12WebSocketServer` | HTTP/WS 连接、认证、协议版本、输入/输出编码、健康检查 | 具体卡牌规则、房间内状态改写 |
| 房间层 | `L12RoomManager` | 建房、入房、座位、匹配、重连绑定、观战权限与生命周期 | 结算卡效、推断对局结果 |
| 对局内核 | `L12GameEngine`及其局部模块 | 命令事务、效果堆叠、Prompt、权威事件、状态与胜负 | HTTP、数据库查询、UI 文案决策 |
| 卡效出口 | 原子目录、运行时路由、组合流程、展示场景 | 将能力身份映射为唯一结算流程与可审计结果 | 绕开内核直接改变状态 |
| 事件/快照层 | 对局事件、状态快照、连接恢复 | 版本化快照、序列、恢复、回放输入与接收者投影 | 通过重放日志猜测私密选择 |
| 持久化/分析层 | SQLite、档案、排行榜、单卡分析 | 写入已完成的权威事实；构建可再生的查询投影 | 参与实时结算或反向修改历史对局 |
| 客户端领域层 | `net.ts`、`platform.ts`、L12 页面/组件 | 连接恢复、状态消费、动作提交、页面与交互状态 | 决定命令合法性或卡效结果 |
| 规则内容层 | `officialRules`、FAQ、卡牌资料、规则中心 | 规则书、术语、FAQ、禁限、赛事规则和版本记录 | 让页面文字覆盖实战权威规则 |

## 四、实施顺序与退出门槛

退出门槛已经满足：

- 取消、拒绝、跳过、失败、无效、目标失效、重复提交、重连、隐藏信息和展示消费者均进入矩阵及代表性回归；
- P0—P6提交`117a3b45`和卡效统一工作台提交`3b79f283`均已推送并完成两次测试服部署验收；最终Release为规则4742/4742、平台149/149、UI契约340，HTTP、WebSocket、版本、324张卡、维护状态和服务稳定性检查通过。

验收结论：**P0 可以退出，可以进入 P1。** P0完成不表示所有复合能力必须立即重写为最细原子；经审定的组合流程和通用权威入口仍是合法唯一所有者。后续原子细化属于受门禁保护的渐进维护，不再阻塞 P1。

### P1：冻结内核边界（已完成，2026-09-24 退出）

为能力目录、路由、事务生命周期、结果投影、快照/回放建立稳定契约和确定性夹具。仅抽取纯读取或已明确写入的端口，保证相同夹具产生相同状态、事件序列和玩家可见结果。

退出门槛：接口契约测试、旧新输出逐项等价、没有新增卡牌旁路、连接恢复和隐藏信息检查通过。

启动边界：先冻结`AbilityId/StructureHash`、运行时路由、命令事务、结果状态、公开范围、事件序列及快照协议的“黄金夹具”；在夹具和等价比较具备前，不移动结算语义、不拆分`L12GameEngine`写入权，也不改变协议或存档格式。P1的首批成果应是契约目录、依赖方向审计和只读/写入端口清单，而不是大规模代码搬迁。

评估吸收边界：现有`SnapshotForInternal()`会对待处理事务执行收敛并可能推进`Revision`，`SerializeFullState()`与`ComputeStateHash()`会先物化V2投影状态，因此这些入口当前不能笼统视为纯读取。P1必须先锁定“先玩家快照、先观战、先状态哈希、先保存”等调用顺序的最终权威状态、事件与各视角投影；只有证明无副作用或显式迁出副作用后，才可命名为只读端口。

事务边界分三层验收：一次命令提交保证状态、事件、请求回执与持久化结果一致；跨多个Prompt的效果流程保证可恢复、费用不重复、步骤不重复结算；对局结束结算保证对局事实、排行与后续投影幂等。P2不得打乱房间层现有的串行锁、请求去重、内核调用、持久化和失败恢复顺序。

已知差异不作为规范冻结：`HAND-ADD-PUBLICITY-AUDIT.md`登记的17组“有条件加入手牌”公开出口已全部统一；已提前公开的路径使用“不重复展示”入口，其余路径使用“公开展示后入手”入口，并由静态守卫禁止重新引入条件检索直加入手的旁路。

实施顺序：P1-A建立契约目录、读写/副作用清单、依赖审计与已知差异；P1-B扩充状态、事件序列、各视角投影、当前版本恢复及读取顺序黄金夹具；P1-C只抽取已经证明边界清晰的少量端口。另建立命令耗时、快照大小、当前版本恢复耗时和数据库写入量基线，历史版本回放性能不作为退出门槛。

退出证据：已建立[P1 对局内核契约目录](l12/CORE-CONTRACT-CATALOG.md)、可执行黄金夹具和内核依赖方向门禁；冻结能力身份、内核端口、命令/Prompt/事件/快照表面、固定命令序列、接收者投影、检查点恢复、隐藏信息以及含孤立Prompt、PendingActivation的读取顺序边界。命令、投影与检查点能力已形成显式端口；快照大小、快照/恢复P95进入预算测试。历史天灾卡号常量已下沉到规则层，59个内核源码对平台存储的依赖为0；17组公开出口全部收口，且没有新增卡牌旁路。

### P2：分离接入、房间与内容投影（已完成，2026-09-24 退出）

将 HTTP/WS 接入、房间生命周期、规则内容查询和后台查询从对局内核外围抽离。先保持同一进程和存储，验证调用方向只从外围进入内核、结果只从内核流向投影。

退出门槛：房间/断线重连/观战权限/协议版本的专项验证；对局内核不直接依赖 UI、HTTP 或分析查询；完整回归通过。

退出证据：房间层只经命令端口进入内核，玩家、观战者、裁判投影统一经`L12KernelProjection`适配器输出；接入层不包含接收者隐私或投影裁剪规则，房间与传输层不得直接改写内核状态。59个内核源码的反向依赖门禁和房间/传输静态边界测试均通过；保持同一进程与现有房间串行、请求去重、持久化及失败恢复顺序，没有引入第二套协议或存储。

### P3：完善现有V2事件与持久化体系（已完成，2026-09-24 退出）

项目已经具备Journal V2追加式命令/事件、检查点、随机状态、请求去重、恢复重放、哈希校验、排位结算outbox和写入失败恢复；P3不另建第二套体系，而是在现有基础上收敛事件契约、当前版本恢复、查询投影、存储可靠性和故障演练。排行榜、战报和单卡分析继续由已确认事实生成，不由前端或分析任务补算卡效。

必须保障当前版本断线重连、重复提交防护、持久化失败恢复与同版本回放一致。跨版本旧回放只在低成本兼容时保留；需要维护旧引擎或复杂迁移时允许明确拒绝，统一提示“该版本已过期，回放无法生成”，同时保留已经确认的胜负和统计事实，禁止用新规则重新推算历史结果。

退出门槛：当前版本恢复/回放一致、协议和存储版本兼容策略明确、隐私投影审计、失败写入恢复、查询投影重建、备份与回滚演练通过；历史版本回放兼容不阻塞P3退出。

退出证据：状态、Journal与最低检查点恢复版本集中在`L12PersistenceContract`，不兼容检查点失败关闭；旧回放统一返回“该版本已过期，回放无法生成”，不以当前规则反算历史结果。既有Journal V2、随机状态、请求去重、哈希校验、排位结算outbox、查询投影和失败写入恢复继续作为唯一体系；当前版本恢复、隐藏信息、分析事实与重放边界测试通过。隔离部署行为的41个场景覆盖外置路径、容量门禁、原子备份归属、精确版本身份及失败关闭恢复，完成备份与回滚演练证据。

### P4：产品结构与移动端体验（已完成，2026-09-24 退出）

规则中心在同一页面内按子页提供核心规则、快速入门、术语与词条、FAQ、构筑与禁限、赛事规则和版本记录。对战、牌库编辑与沙盒按实际可视区比例选择逻辑横向画布和移动密度，不依赖设备身份或物理方向；旋转只作用于显式加入的路由画布及其弹框宿主，不影响冻结的桌面宽屏布局和其他页面。页面规则始终使用 L12 术语和权威资料。

退出门槛按项目现有资料调整为：公开规则内容能够追溯来源和版本状态；权威来源提供记录日或生效日时必须保留并展示，来源本身未提供日期时必须明确说明“未提供/待发布”，不得为了满足格式而伪造日期，也不要求每个词条重复保存同一份文档级元数据。移动端对局须经目标视口、Prompt/支付/重连/隐藏信息测试，桌面基线不得回归。

退出证据：

- 规则中心已经在同一页面提供核心规则、快速入门、术语、FAQ、构筑与限制、赛事规则和版本记录七个子页；玩家页只读取管理员已发布内容，待审核条目不会公开。规则书、裁定和运营限制分别保留来源、版本/记录状态；原始规则书未给出公开生效日期的事实在版本记录中如实披露。
- 规则中心逐项发布不会连带公开同集合的其他草稿，平台内容专项18/18通过；移动竖屏筛选默认收起并保留搜索入口，现有站点页面不需要横向滚动来完成主要操作。
- 对战、牌库编辑和沙盒只在路由显式标记`landscapeCanvas`时进入逻辑横向画布；判定读取实际`visualViewport`几何与用户“自动/始终启用/使用宽屏布局”设置，不读取设备身份或物理方向。旋转、坐标映射、安全区和弹框宿主均限制在该画布内。
- 移动对战已覆盖11档视口、127组主状态、64组弹框、12组安全区、36组焦点恢复、四档工具弹层；Prompt、支付、最小化/恢复、动作命中、断线恢复、隐藏信息和移动端回放禁用均进入现有门禁。五档桌面隔离验证确认移动规则未侵入宽屏基线。
- 本次退出没有为“完成阶段”新增第二套布局、内容模型或日期字段；以当前实现和可重复门禁收口，后续视觉或规则内容调整继续作为独立产品批次处理。

验收结论：**P4 可以退出，当前《十二军团架构目标》列出的P0—P4均已完成。** 此后新增阶段必须先有新的明确目标、边界和退出门槛，不能借“继续架构优化”无界扩张。

## 五、明确禁止的捷径

- 以“P0—P3已经完成”为理由直接大拆`L12GameEngine`、替换 WebSocket 协议或迁移存档格式；后续动作仍必须经过既有契约、等价验证和兼容策略门禁。
- 让前端、后台、FAQ 页面或分析任务执行/修正规则结果。
- 以卡名、自然语言匹配或展示文案充当新的实战路由。
- 用“已构建成功”代替规则、恢复、可访问性或视觉验收。
- 把外部同类游戏的术语、卡效、数值、裁定或 UI 直接复制到 L12。
- 因共享项目名而假定跨任务已同步；未提交差异与对话计划必须显式交接。

## 六、协作与集成目标

1. `D:\GPT\Legion12\app`作为规范工作区；隔离 worktree 只用于明确的变更批次。合入前以`origin/main`与实际工作区状态为准。
2. 每个并行工作流须记录：负责人、基线提交、可写文件、禁止文件、首个交付物、验证项与回传对象。一个文件同一时刻只有一个写入者。
3. L12-Main 负责需求裁定、集成、共享台账、最终验证、Git 同步、玩家更新日志和部署。专项任务只交付有边界的方案、差异和验证证据，完成后显式回传 Main。
4. 每次生产部署都以已验证候选为单位，玩家更新日志只说明玩家可见变化；部署必须取得该批次明确授权。
