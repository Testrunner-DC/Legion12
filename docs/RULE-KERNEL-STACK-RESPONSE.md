# 效果类型、堆叠与响应：规则内核不变量

更新日期：2026-08-28

本文件把《十二军团》规则书“效果类型、堆叠与响应”固化为服务端、前端、后台原子化与测试共用的不可回滚约束。单卡实现只能组合这些规则，不得另建时序捷径。

## 1. 五种效果类型

| 类型 | 是否有发动动作 | 是否进入响应流程 | 执行要求 |
| --- | --- | --- | --- |
| 规则效果 | 否 | 否 | 始终调整基本规则；由规则查询或替代效果处理 |
| 持续效果 | 否 | 否 | 条件符合期间立即重算；不得伪造成触发或弹框 |
| 主动式效果 | 是 | 是 | 玩家宣言后按“预声明—校验—支付—入栈—响应—结算”处理 |
| 触发式效果 | 是，但只能在触发时机发动 | 是 | 收集同一时点触发；“可”才允许不发动；由拥有者排序 |
| 反应式效果 | 是，仅限对应响应时机 | 是 | 必须满足公开时机和自身真实合法条件后才能入栈 |

天灾属于特殊触发式效果，但具有更高优先级：等待当前及待处理堆叠全部结束后触发；不能被响应或无效化；其导致的登场、离场或阵亡不触发普通卡牌效果。

## 2. 发动事务的唯一顺序

主动式、触发式和反应式效果统一执行：

1. 确认发动时机、来源与控制者合法。
2. 预声明模式、目标、战场位置及额外费用选项。
3. 一次性校验全部声明和全部费用；不允许先支付一半再询问剩余费用。
4. 原子支付冒号前全部费用。
5. 将效果与已声明信息加入堆叠。
6. 开启对应响应窗口。
7. 双方连续让过后按后发先至结算。
8. 结算时目标失效只影响无法处理的部分；已发动效果不因来源离场而失效，除非卡面另有说明。

取消只能发生在费用支付与入栈之前。进入堆叠后不能用“取消”撤销发动。

## 3. 同时触发、待处理堆叠与优先权

- 同一时点的全部触发先收集成批次，不得边扫描边结算。
- 当前回合玩家先排列自己的全部触发；再由对手排列自己的全部触发。
- 当前响应窗口由当前回合玩家先取得优先权。玩家可连续加入任意数量合法响应，直到主动让过。
- 一方让过后优先权交给另一方；双方在同一窗口连续让过后，立即结算当前堆叠顶部，不再次提示同一窗口。
- 新效果进入堆叠后形成新的响应窗口，优先权和连续让过计数重新开始。
- 当前堆叠结算期间产生的新触发形成待处理的新堆叠；当前堆叠完成后，待处理堆叠仍按后发先至处理。
- 所有普通堆叠与待处理堆叠完成后，才检查并触发天灾。

## 4. 响应窗口与隐藏信息

- 窗口是否出现，只能依据主宰兼容卡池、公开时机和公开场面判断；不得读取手牌真实身份或盖牌卡号来决定是否提示。
- 窗口中的真实可选项，只列出该玩家实际持有且当前合法的卡牌或效果。
- 公开状态存在理论响应、但玩家没有真实合法选项时，只提供“让过”，以免窗口行为泄露隐藏信息。
- 公开快照相同的两局，即使隐藏手牌或盖牌不同，也必须具有相同的响应窗口可见性。
- 同一响应时机双方均已让过后不再重复开启；只有新响应入栈才重置优先权。

## 5. 可响应与不可响应边界

可响应的公开时机包括：

- 阶段开始或结束；
- 卡牌打出；
- 主动式、触发式或反应式效果发动；
- 军团移动。

不可响应的项目包括：

- 费用的获得与支付本身；
- 规则效果与持续效果；
- 覆盖反击战术这个规则行动；
- 静态的“进攻无损”“远程进攻无损”等持续能力；
- 天灾的触发与结算。

## 6. 进攻中的堆叠边界

进攻必须按规则时序分段，不能把进攻时效果、对方反应、抵挡和支援同时弹出：

1. 宣言进攻：进攻军团转为休整，锁定进攻者并选择距离、挑衅等规则均合法的目标；目标由此成为被攻击者。
2. 完整结算进攻方的【进攻时】触发及其响应；只有该组堆叠清空后，才建立防守方【对方进攻时】时点。
3. 完整结算防守方【对方进攻时】及其响应；随后重新确认进攻者与目标仍在合法区域，并冻结进入防御时的本次进攻数值。
4. 目标为主宰时，防守方可用手牌中合计兵力不低于冻结进攻值的军团抵挡；目标为军团时，只有同列后排军团可支援，且其与目标合计兵力须不低于冻结进攻值。
5. 支援时支援者阵亡，交战双方均不减损兵力且不产生【击杀时】。未支援时按冻结进攻值与双方当时兵力结算伤害和致命替代。战斗伤害先消耗本次进攻、本回合及持续正兵力层；效果结束只移除该层尚未被伤害消耗的部分，不得再次扣除已经吸收伤害的加成。
6. 战斗伤害击杀对方军团的每一方都产生自己的【击杀时】；FAQ 19 明确规定双方同归时双方均有击杀。战斗后子阶段固定为进攻者【击杀时】、防守者【击杀时】、进攻者【阵亡时】、防守者【阵亡时】；不存在的阶段跳过。这些触发全部完成后，阵亡军团才进入墓地。
7. 战斗存活的进攻者结算【进攻后】，被攻击军团结算独立的【被进攻后】/防守方公共钩子；全部结束效果完成后才回到主要阶段。

每一子阶段必须先写入可重连状态再建立 Prompt/Stack。进攻者或目标在任一堆叠后的安全边界离场时，自动终止尚未发生的战斗步骤并回到主要阶段，不追溯取消已经发动或结算的效果。贯穿等嵌套进攻须挂起并恢复父进攻上下文。远程进攻无损是持续效果，不产生发动或被无效化的时机。

## 7. 试炼与天灾的区别

- “发动试炼”是阵营规则行动，不等同于试炼军团的“推进试炼”动作。
- 试炼卡满足条件后产生的效果按其印刷类型处理；若为触发式效果，则进入堆叠并可被响应。
- 天灾虽然属于特殊触发式效果，但按本文件第 1 节的特殊规则处理，不套用普通试炼或普通触发的响应窗口。

## 8. 最低回归门禁

任何涉及效果时机、Prompt、堆叠、进攻、隐藏信息或天灾的修改，至少验证：

1. 五种效果类型没有互相误判。
2. 目标、模式、位置和额外费用在支付前完成预声明。
3. 费用失败不产生部分支付或重复支付。
4. 一般同时触发遵循当前回合玩家先建立批次、双方各自排序；战斗死亡严格使用第 6 节的击杀/阵亡顺序，不合并成 AP/NAP 批次。
5. 双方连续让过只结算一次，新响应正确重置优先权。
6. 隐藏信息不同但公开快照相同时，响应窗口行为一致。
7. 堆叠中新增触发延后处理，且天灾最后检查。
8. 进攻方【进攻时】、防守方【对方进攻时】、抵挡/支援、冻结数值伤害、击杀/阵亡和双方结束钩子不并发错序；重连快照能恢复当前子阶段。
9. 规则/持续效果及费用支付不产生响应窗口。
10. 完整后端回归、前端契约检查、构建和 git diff --check 全部通过。

## 9. 实现禁令

- 不得用单卡卡号直接决定公共响应顺序、优先权或堆叠结算。
- 不得用 EffectText.Contains 作为实战效果类型、响应资格或战斗能力的权威判断。
- 不得在费用支付后才询问目标、模式、位置或是否支付额外费用。
- 不得因效果来源离场而擅自取消已经发动的效果。
- 不得为修复单卡而绕开 PendingActivation、TriggerBatch、响应窗口或派生状态公共框架。
- 不得以“到期重建为原本兵力 + 当前修正”清除伤害或恢复已消耗的临时兵力层；兵力伤害必须进入公共伤害入口。
