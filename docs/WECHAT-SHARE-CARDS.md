# 微信分享卡片

## 已实现范围

- 主页、资讯列表和资讯详情的首个 HTML 响应由服务端输出 `title`、`description`、`og:title`、`og:description`、`og:image`、`og:url` 和 canonical URL。
- 资讯详情只读取已发布快照。草稿、撤回稿以及尚未再次发布的编辑不会进入分享信息。
- 资讯标题使用已发布标题；摘要从结构化正文或旧 HTML 正文提取纯文本并截取约 80 个文字元素；封面优先，未设置封面时使用正文首图的桌面交付图，再无图片时使用 650×650 的站点 Logo。
- 图片和页面地址统一转换为当前环境 `L12_PUBLIC_BASE_URL` 下的 HTTPS 绝对地址；测试路径因此使用 `/testrun` 前缀，不会错误指向正式 API。

## 请求链路

Nginx 只把主页、资讯列表和单篇资讯的文档请求转给 `/_l12/share-page`。静态资源、API、WebSocket、卡图和其他页面仍走原有链路。正式部署会在新服务健康后安装并验证分享路由；失败时 Nginx 配置自动恢复。测试子域模板和 `/testrun/` 挂载模板均包含同一链路。

前端 `index.html` 自身保留默认 Open Graph 信息，因此未经过动态路由的普通页面也不会退回裸链接。动态渲染只替换 `l12-share-meta` 标记区，不改写应用脚本和样式引用。

## 验收

1. 在微信中首次分享 `https://legion-12.com/`，检查标题、简介和站点 Logo。
2. 分享一篇带封面的已发布资讯，检查发布标题、正文摘要和封面。
3. 分享一篇无封面但正文含图的已发布资讯，检查正文首图。
4. 修改标题但仅保存草稿，旧分享信息应保持；再次发布后使用未分享过的查询参数或新文章验证新标题。
5. 撤回资讯后，其路径只返回站点默认分享信息，不泄漏撤回内容。

微信可能缓存同一 URL 的卡片。验收内容更新时应使用新文章，或添加此前未分享过的无业务含义查询参数；服务端 HTML 设置为 60 秒重新验证，但无法强制清除微信客户端缓存。

## JSSDK 边界

当前实现不依赖微信 JSSDK，因此不需要公众号凭据，也不会把任何密钥写入仓库。只有在确认已认证公众号、JS 接口安全域名和后端签名凭据后，才考虑增加 `updateAppMessageShareData` / `updateTimelineShareData`；Open Graph 服务端输出仍作为基础能力保留。
