# 对战玩家信息阶段 2：通用选择弹框首批验收

范围：`PromptOverlay.vue`、`PromptCardCandidate.vue`、预览/浏览器验收脚本，以及 Main 放行的服务端不可选原因生产入口与对应测试。以阶段 0/1 的提示清单与展示契约为依据；不修改规则、可选目标集合、服务端判定或记录。分支 `codex/battle-player-information-full-20260928`，基线 `d2206cc274e3a3618830ba637383071124807529`。

## 玩家能看到什么

- 标题与当前情况之后，明确显示当前操作方（由 `prompt.playerIndex` 与 `game.you` 判定）、本步需要选择的数量，以及服务端提供的操作说明。
- 费用只按服务端 `paymentStatus` 与 `paymentSummary` 显示“已支付”或“待支付”；确认后果和退出选项后果继续使用服务端 `PromptPresentation`，不在前端推断退款或结算。
- 卡片选项的可访问名称包含卡名、当前位置、当前兵力和状态、选择后果及不可选原因。聚焦或触摸后，正文内的详情条也展示这些字段；同名军团可按“我方前排左格”等战场位置区分。
- 最小化后的条目保留当前操作方、任务、数量和费用摘要。展开与收起时将键盘焦点移到对应按钮；长内容在弹框正文内滚动，底部操作保持可达。

## 阶段 2 后续响应子批

[响应时序只读审计](BATTLE-RESPONSE-TARGET-ORDER-AUDIT-20260928.md)已按共享入口区分先选目标后响应、先响应后选对象及仅显示来源的场景。后续响应子批先在服务端冻结已选目标、接收者可见名称/格位/公开数值与事件顺序，再接入弹框；不以客户端延时或猜测改变响应语义。目标失效、取消、无目标、独立后续段、旧检查点与四类接收者须按阶段 0/1 硬标准逐项验收。本批不可选原因工作不改响应流程。

## 明确边界

- 首批验收发现 `L12RuleKernelIntegration.cs` 的激活选项分支之外未发布 `disabledChoice:<id>`。Main 放行有界扩展后，公共墓地展示与六组牌库查看/筛选生产入口已按原合法集合发布原因；缺失原因的旧 Prompt 仍只显示“当前不可选择”，不伪造规则解释或向玩家暴露系统状态。
- `cardSelection` 之外的预览卡不会被错误标为“不可选择”。隐藏的对方战场牌只显示位置，不从本地对象泄露名称。
- 这一批尚未处理战场内嵌选择、时间条、攻防/支援、卡牌顺序、记录缺口。
