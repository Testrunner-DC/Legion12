# F3：Snapshot 读取顺序对抗验证（2026-10-02）

本批只新增验证代码和证据，**没有改变规则内核、读取路径、持久化或恢复语义**，没有读取线上对局或部署。对应测试：`TwelveLegions.Tests/ArchitectureF3SnapshotReadOrderTests.cs`。

## 方法

- 固定随机种子和 UTC 时钟，对同一确定性原始状态分别建立独立引擎；四种读取者为双方玩家、公开观战、裁判。穷举四种视角的 `4! = 24` 种读取顺序，每种视角连续读取两次。
- 正常状态覆盖：先后手选择提示、换牌阶段、换牌完成后、从检查点恢复后。损坏态单列为故意注入的孤立 activation prompt，不混称正常对局。
- 每次比较四视角各自的完整投影摘要，以及读取前后的权威状态序列化摘要、Revision、事件和待处理提示；视角读取完毕后才计算权威状态哈希，并检验哈希计算没有再改变状态。不同权限视角**不相互比较内容**，只比较同一视角跨顺序是否稳定。哈希计算本身也可能整理异常状态，所以不能在首个视角读取前调用它来冒充纯观察。
- 专项运行：`dotnet test TwelveLegions.Tests/TwelveLegions.Tests.csproj --no-restore --filter FullyQualifiedName~ArchitectureF3SnapshotReadOrderTests --verbosity quiet`；D 盘工作区与 NuGet 缓存，5 项通过、0 失败。最终候选完整 Batch 规则 6070/6070、平台 301/301 通过。

## 结果与判定

| 情形 | 顺序对比 | 读前/读后权威状态 | 判定 |
| --- | --- | --- | --- |
| 四类正常状态 | 每类 24 种顺序，四种投影、重复读取、最终状态哈希及权威状态均一致 | 状态、Revision、事件、提示均不变 | 本次样本未发现正常路径读取次序依赖。 |
| 故意孤立提示 | 24 种顺序最终一致，四种投影各自一致 | 首次读取触发既有修复：Revision `+1`、提示移除、事件变化；之后稳定 | 源码中的读取副作用在损坏态确实可观察；不能把它直接称为线上正常态竞态。 |

源码核对：`L12GameEngine.SnapshotForInternal` 会先调用 `ReconcilePendingActivationTransactions()`，必要时推进 Revision，然后准备投影；`ComputeStateHash()` 也会准备 V2 投影。既有 `ArchitectureP1CrossLayerGoldenTests` 已记录孤立提示导致读取前后持久化不同，本批把双方玩家、观战、裁判的排列及正常检查点路径补齐。

**F4 门槛结论：**当前没有正常路径顺序依赖证据，不自动启动 P1/P3 锁定边界内的读取副作用迁移。若以后真实日志或更长链路复现正常态问题，应保存脱敏原始检查点、命令/Journal 与视角读取次序，在独立审批批次中扩充 F3 反例，再决定 F4；不得因本报告擅自修改恢复语义。

限制：本矩阵不是全卡效、全部响应窗口或线上并发压力覆盖；固定时钟用于排除自动响应倒计时的自然时间漂移。结论仅限上述状态和当前提交，不代替 Release 全门禁。
