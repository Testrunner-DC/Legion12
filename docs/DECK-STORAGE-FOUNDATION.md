## 2026-09-24已实现边界（历史）

- SQLite 架构版本升至 4，牌库域从 `platform_state.snapshot_json` 与 JSON 兼容镜像拆出。
- `deck_payloads` 按“主宰＋区域＋卡号＋数量”的确定性结构计算 SHA-256；主牌、士气、额外区分别排序并压缩为卡号与数量。卡名、效果、费用、卡图、派生统计和异画选择均不进入规则正文。
- 账号牌库、公开牌库当前版本、全部公开历史版本和赛事报名快照只引用正文哈希。同一构筑跨账号、公开和赛事只保存一份正文。
- 账号牌库与公开牌库删除采用逻辑删除；历史版本、赛事引用与暂时无引用正文不自动清理。
- 公开牌库的浏览、复制和点赞使用局部 SQLite 原子事务，不再提升平台快照版本，也不再重写全量 JSON 兼容镜像。
- `StorageStatus()` 增加正文、账号牌库、逻辑删除牌库、公开牌库、公开版本、点赞、赛事引用以及数据库/WAL 字节数。

## 迁移与切回

1. 首次读取旧快照时，先把含完整牌表的旧状态压缩为唯一的 `platform.db.pre-deck-domain-v1.json.gz`。
2. 同一 SQLite 事务内写入正文和全部引用，并逐条比较账号、公开、赛事引用的规范化哈希。
3. 只有完全一致才写入 `deck_domain_state=active-v1`，同时将不含完整牌表的平台快照提交；校验失败则事务整体回滚，旧快照继续有效。
4. 数据库提交后再原子更新 JSON 兼容镜像；镜像失败不会回滚已验证的 SQLite，但会在存储状态中报告。
5. 预迁移`.json.gz`仅为历史恢复证据，**不能作为上线后普通回退的最新数据源**。一旦新服务可能写入，禁止以迁移前JSON或旧数据库覆盖最新`.db`/WAL。回退必须基于当前最新事实、同版本受控反向转换或已明确证明兼容的程序包，完整保留ID/修订/公开历史/赛事引用；未通过对应演练和当批权限不执行。新A格式反迁移仍为待实施出口，不把本段当作已经可运行的工具。

## 永久保留规则

- 不按时间、版本数量或引用状态删除 `deck_payloads`。
- 公开版本超过 20 个仍全部保留；相同正文重复发布不新增版本。
- 赛事锁定牌库由 `tournament_deck_refs` 长期引用，账号后续修改不改变已登记正文。
- 玩家主动删除牌库只隐藏账号/公开入口；正文和公开历史不物理删除。
