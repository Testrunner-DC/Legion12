## 2026-09-13 私有手牌登场响应：摄政皇权与暗度陈仓

摄政皇权与暗度陈仓现各自拥有第1/1段稳定组合场景。卡文、声明事件、实际结算、动效、日志与回放读取同一段定义；私密手牌实例仍只保存在权威声明事务和StackItem中，不进入公开场景定义或分支条件。摄政皇权继续支持特殊军团允许的战场选择，暗度陈仓继续限定费用不高于4的【天廷】军团与我方空位。

两者都在入栈前一次性复验手牌对象、战场与位置；暗度陈仓还先复验士气，再返还1士气并入栈。入栈后对象离手、费用变化、阵营条件失效或位置被占用，现统一记为`failed`，不再让摄政皇权静默成功或把暗度陈仓误记为“选择不发动”；暗度陈仓已经支付的士气不退。选择`mode:none`则保持盖牌、士气和手牌不变，不入栈，重复提交旧Prompt被拒绝。

成功、结算期失效、选择不发动、重复提交与检查点恢复均由真实路径或冻结StackItem具名覆盖；聚焦84/84、完整Batch规则2930/2930零失败零跳过。复合旧响应体由7个降为5个：不朽之礼、切腹仪式、地主的胁迫、乾坤·阴、特洛伊木马；下一批优先不朽之礼与切腹仪式的多结果/部分结算边界。

## 2026-09-13 复合响应分支首批：绝对防御与拼死反抗

绝对防御现按玩家实际选择的当前堆叠项目冻结公开分支：直接响应`opponent-attack`进攻宣言时为“抵挡本次进攻”，响应进攻链或普通链上的效果时为“无效该效果”。判断不沿响应链回溯根时点，因此用绝对防御无效另一张反击战术不会误显示成抵挡。两种分支共用原弃置手牌Cost、响应资格和`response-negate`运行结算，但声明、实际结果、动效、日志与回放拥有不同稳定场景身份。

拼死反抗现把玩家在翻开前声明的单体/全体模式冻结到StackItem：单体分支为所选休整军团-2000，全体分支为结算时所有休整军团-1000。单体对象在结算前离场或转为活跃、全体分支结算时已无休整军团，均记为`skipped`而不是伪记成功；响应自身被无效仍记`negated`。分支和结果状态随检查点恢复，费用/翻开状态不回退。

本批聚焦54/54、跨战斗/嵌套响应189/189、完整Batch规则2922/2922零失败零跳过。9个复合旧响应体已迁移2个，剩余7个：摄政皇权、不朽之礼、切腹仪式、地主的胁迫、乾坤·阴、特洛伊木马、暗度陈仓。下一批优先把摄政皇权和暗度陈仓的私有手牌选择/登场位置接入组合段，并保留声明失效不卡死、取消恢复响应优先权与重连复验。

## 2026-09-12 单段响应运行时映射首批

## 类型与验收

全池按卡号+能力+段登记：登场、阵亡/离场、进攻/伤害、主动、反击、试炼/符文、费用/士气、目标替换/免死/击杀、天灾、多段分支。同卡允许多类型。

仪表盘仅后台使用，展示样本、置信度、版本/时间范围与排除原因，不新增玩家评分、推荐卡组或自动强度结论。

## 效果一致性完成后的阶段：后台卡效工作台

状态：已纳入本次实施计划，作为效果生命周期、逐能力结构和展示同源完成后的正式阶段；当前不抢占对战可靠性与效果一致性优先级，不提前把尚未稳定的运行协议固化进编辑器。

目标是让维护者在后台基于现有原子化能力自行完成卡牌规则和呈现配置，不再依赖逐条对话修改代码。后台必须围绕同一份带版本的结构定义集纳：

- 卡牌基础资料、所属产品/收录产品选择、版本、印刷状态与生效范围；
- 按独立能力和效果段撰写的卡文，包括时点、必发/选发、冒号前Cost、候选、目标、响应、分支、结算、状态与公开等级；
- 勘误记录，包括原文、新文、原因、生效版本/时间、影响产品、关联能力段、历史修订与回退记录；
- 卡牌按钮、发动/支付/目标/响应弹框、成功/跳过/无效/失败日志，以及回放摘要所用的分支化文本模板；
- 一张卡或单个效果段的呈现样式，包括卡牌展示、来源强调、目标高亮、费用支付、响应、分支选择、结算与结果动效。

呈现样式不得让维护者面对无说明的内部枚举。每一个可选样式都必须在选择器内提供名称、适用场景、静态图例或可播放范例、桌面与移动端预览，以及公开信息说明；需要参数的样式同时展示默认值和当前效果的实际预览。范例素材随样式版本管理，删除或修改样式时不得破坏旧录像和进行中对局的冻结呈现。

后台采用“卡牌 → 能力 → 效果段 → 运行步骤/展示投影”的层级编辑，提供图鉴卡文、玩家按钮、各阶段弹框、响应方视角、动效、日志和回放的并排预览。界面只提供受约束的原子、条件、目标、费用、响应与样式选项，不允许录入任意服务端代码；高级规则无法表达时进入待开发状态，不能以自由文本冒充已接运行时。

发布流程固定为草稿 → 结构校验 → 场景预演 → 人工复核 → 生成差异 → 发布。校验至少覆盖能力分段、Cost可支付、候选与目标、公开/私密信息、响应范围、无对象策略、重复提交、恢复版本、文本变量和样式兼容性。已发布版本不可原地覆盖；进行中对局、录像和日志绑定冻结的规则/展示版本，并支持审计、回退和导出。

### 后台布局与视觉规范

- 先建立并复用后台设计系统：按钮层级、尺寸、间距、圆角、颜色、图标、表单、卡片、标签、弹框、空状态、错误状态和响应式断点统一；不得为单个功能临时拼接一套按钮样式。
- 主操作、次操作、危险操作和只读状态必须有稳定层级；同一区域的按钮高度、对齐、文案密度和点击区域一致。类似近期“改选派系”这种新增入口必须回归统一组件后才能验收，不以功能可点击代替视觉合格。
- 复杂编辑器使用清晰的分栏、折叠与固定预览区，避免一屏堆满字段；窄屏允许转为单列，但不得遮挡保存、校验、预览和返回入口。
- 每次新增后台功能必须同时提交桌面、窄桌面和平板/移动宽度的真实渲染证据；检查深色主题、长中文、空数据、错误提示、键盘焦点和触控区域。视觉验收与功能测试同为发布门禁。

### 分期与验收

1. 在效果一致性完成后冻结第一版规则/展示Schema及版本策略。
2. 建立只读卡效工作台，先汇总现有原子能力、卡文、勘误、产品、弹框、日志和呈现来源，并标记仍属硬编码或重复来源的字段。
3. 开放草稿编辑和全视角预览；先覆盖新增卡和高风险效果，不一次迁移全部旧卡。
4. 接入校验、测试场景生成、审核、差异、发布、回退和审计权限；后台发布仍须通过现有Focused/Batch/Release门禁。
5. 最后迁移存量卡，并持续禁止运行时按卡文猜测规则或由多个界面各自维护文案。

完成标准：维护者可以在后台选择产品、拆分能力、配置Cost/目标/响应/分支、撰写卡文与勘误、选择带图例的呈现样式，并同时预览按钮、弹框、动效、日志与回放；一次审核发布生成同一版本的运行定义和各界面投影。任一字段超出Schema、预览与运行结果不一致、缺少移动端/视觉证据或旧对局无法恢复时，均不得发布。
