## 实施结果

- 审计源明细超过30天后，先写压缩 JSONL，校验文件及逐条载荷、编号、事件日期，再在事务内迁出源明细。归档按事件时间超过180天淘汰，不按归档创建日期延期。
- 用精确事件编号墓碑及数据库触发器阻止旧平台镜像重新导入已迁出事件；墓碑不保存原始正文。旧手工归档只校验和过期清理，不改造旧格式。
- 文件写入、源事务、文件删除均有可恢复阶段。损坏、保护命中或引用信息不可得时保留现场。未完成事故、运行/恢复/结算依赖保留；缺少可靠闭环的排位、发布及失败审计保守保护，不宣称全部历史记录自动删除。
- 测试服已结束超过14天的合格对局清理回放载荷与无用单卡事实；保留赛果、构筑、汇总与结算凭据，保护 Bug、活动、恢复、隔离及仍依赖旧检查点的排位记录。
- 测试清理必须同时满足明确测试标记、准确 HTTPS 域名、独立物理目录及证据快照。发布目录 runtime 链接允许解析至测试物理目录，不能指向正式库。正式服务不能误用此策略。
- 每天北京时间04:00串行执行，轮换任务先后顺序；共用10秒软预算、单项最多3秒。游标有界续扫，保护记录不会永久堵住后续记录，不增设高频扫描或新计时器。
